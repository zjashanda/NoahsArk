## 0. 研究记录（Research Log）

### 0.1 Design Read

这是一个 **运营型档案工具**，不是营销页，也不是聊天应用。用户是测试工程师、测试负责人和平台管理员，在长时间、高强度、多人协作的环境里判断三件事：

1. 现在有没有任务卡住，卡在谁那里。
2. 这个结论能不能信，证据链是否闭合。
3. 我按下去的这个按钮，会不会造成不可逆后果。

因此设计目标不是“看起来像 AI 产品”，而是 **让判断变快，让误判变难**。视觉必须可识别：像一本正在被填写的航次档案，而不是通用深色 SaaS 模板、终端聚合器或聊天壳。

### 0.4 锁定的设计方向：航次档案（Voyage Ledger）

在三个方向中选定一个，不做平均：

| 方向 | 描述 | 结论 |
|---|---|---|
| A. 深色驾驶舱 | 黑底、霓虹蓝、发光卡片、终端感 | 拒绝：通用 AI 控制台惯性，且难以承载长时间阅读 |
| B. 航次档案 | 暖白档案纸、深墨绿文字、海青航向、朱砂人类批注 | **选定**：与 ark 母题同源，能把“证据、门禁、批注”变成可见的纸面结构 |
| C. 霓虹数据舱 | 紫红渐变、玻璃拟态、悬浮卡片 | 拒绝：典型 AI slop，与可追溯语气冲突 |

**一句话方向**：像一本正在被填写的航次档案：暖白纸张、细墨线、海青色航向标记、朱砂色人类批注；每一个结论都钉在可回溯的证据页上。

- **氛围**：暖白纸面，不是纯白；页面边缘有 3% 的横向档案纸纹，像一叠装订好的记录。
- **材质**：哑光纸张与 1px 墨线。卡片是“档案卡”，不是玻璃糖果；只有弹层、命令面板与接管终端允许浮起。
- **色彩故事**：海青 = 可操作与航向；朱砂 = 人类注意与等待；海玻璃绿 = 已核验证据；氧化红 = 失败；深墨 = 未决文本。彩色只占约 10%。
- **签名时刻**：任务详情顶部的 **七枚门禁印列（C1 至 C7）** 与总览右侧的 **决断页边（Decision Margin）**。用户一眼看到“船到哪一段、哪一页还没有批注”。

### 0.5 从第一性原理保留的非默认决策

1. **浅色档案纸为唯一全局主题**：画布 `#F4F0E6`，文字 `#1B2A2E`，不用黑底。只有终端与接管局部使用深色 `#12211F`，因为机器输出需要与纸面区分。
2. **用细线与字阶做层级，而不是阴影**：卡片 1px `rgba(27,42,46,0.20)` 边界 + 2px 偏移印刷阴影；不做发光、玻璃、渐变描边。
3. **等宽字体承载事实**：任务 ID、哈希、版本、租约 epoch、事件 seq 全部使用 `--na-font-mono` 与 `tabular-nums`。
4. **唯一朱砂色只给人类**：`#B8482C` 只用于等待人工、接管、审批与人类阻塞；普通警告使用赭石 `#8F5A18`。
5. **门禁印列不是进度条**：C1 至 C7 是七枚离散印章，不能用一根连续进度条代替；连续进度只描述阶段。
6. **拒绝彩色侧边条**：卡片、提示、选中行都不使用左侧色条或彩色描边。状态由印列、文字、底色与形状共同表达。

## 1. 品牌

### 1.1 名称与定位

- 产品名：**NoahsArk**（固定大小写，不写 Noah's Ark、Noahs Ark、NOAH'S ARK）。
- 外壳名：**NoahsArk Console** / **NoahsArk 控制台**。用于页面标题、状态缎带、文档与关于页；不使用其他控制室式命名。
- 中文名：**方舟**。用于品牌叙事与空状态，不替代产品名。
- 定位：**AI 资深测试工程师平台**。不是任务队列，不是终端聚合器，不是聊天机器人。
- 品牌承诺：**让每一次测试结论都可复现、可追溯、可复用。**

“方舟”在这里的含义是：在一次次不确定的测试洪水中，保存真正有效的计划、证据、失败模式与修复经验，让下一个任务不必从零开始。不使用宗教图像、不复制任何现有方舟标志、不使用诺亚人物形象。

### 1.2 品牌叙事（用于登录页、关于页、空状态）

> 每一次测试都会留下两样东西：一个结论，和一条能回到结论的路。
> NoahsArk 把这条路保存下来。下一次，船不必重新造。

语气要求：冷静、具体、承认不确定性。禁止“魔法般”“一键智能”“永不失败”等承诺。

### 1.3 Logo 概念与构造

文件：`assets/brand/ark-logo.svg`（64 × 64，透明底，内联 SVG，无外部字体/图片）。

构造：

| 部件 | 含义 | 形式 |
|---|---|---|
| 船体节点链 | 证据链与 AI 网络合为一体 | 五个节点由四段弧线连成收拢的船底，读作 ark，不是普通帆船 |
| 甲板 | 把网络固定在真实执行环境上 | 1.6px 水平结构线，圆角端点 |
| 桅杆 | 平台主轴与执行链 | 2.2px 垂直主线，从甲板升至上方网络 |
| 张索 | 规划、执行、验证三条链路 | 1.3px、50% 透明度的两条斜线 |
| 网络节点 | 证据与协作 | 海青 `#1F5F5B` 实心圆，直径 3.8 至 4.4 |
| 桅顶信号 | 人类决断 | 全图唯一朱砂 `#B8482C` 实心圆，直径 5.4 |

使用规则：

- **主色变体**：线条 `currentColor`（纸面为 `#1B2A2E`），船体节点固定 `#1F5F5B`，桅顶信号固定 `#B8482C`。
- **单色变体**：全部 `currentColor`，用于单色印刷、禁用态、水印；不得改变节点位置。
- **反白变体**：深墨底使用 `#FCFAF4` 作为 `currentColor`，船体节点改为 `#89B7AA`，信号仍为 `#E3A18B`（保证深底对比）。
- **最小尺寸**：屏幕 20px，印刷 8mm。小于 20px 时使用简化版（仅船体节点链 + 桅顶信号），由实现方按同一几何裁切。
- **安全区**：四周至少留出船体宽度的 25%（约 12px @64）。
- **禁止**：拉伸、旋转、加投影、加渐变、把信号节点改成海青、把 logo 当作普通“首页”图标重复使用、在 logo 内加文字。

### 1.4 品牌字标（Wordmark）变体说明

SVG 只交付图形标。字标在文档中定义，不嵌入 SVG 字体：

```
[ark 图形 28px]  8px 间隙  NoahsArk
                            AI TEST PLATFORM  ·  方舟
```

- 字体：`--na-font-display`（Sitka Banner / 档案体），字重 600，字号 18px（桌面命令甲板）/ 16px（紧凑），字距 `-0.01em`。
- 颜色：`Noahs` 用 `--na-text-primary`（`#1B2A2E`），`Ark` 用 `--na-brand-500`（`#1F5F5B`）。不使用渐变。
- 描述行：`AI TEST PLATFORM` 10px 等宽大写，字距 `0.18em`，颜色 `--na-text-tertiary`；中文“方舟”只在关于页与品牌页出现，不进入日常命令甲板。
- 锁定组合：图形与字标基线对齐，图形垂直居中于字标 x-height；不得把字标放进胶囊或描边盒。
- 单色场景：整个字标使用 `currentColor`，`Ark` 不再单独着色。
- 应用图标：图形放入 64px、圆角 4px 的 `#F4F0E6` 底，图形占 44px，安全区 10px，外框 1px `rgba(27,42,46,0.20)`。

### 1.5 文案与语气

| 场景 | 规则 | 示例 |
|---|---|---|
| 页面标题 | 名词短语，不超过 8 个汉字 | 任务、知识、节点与设备 |
| 按钮 | 动词开头，说明后果 | 批准计划、开始执行、停止任务、接管会话 |
| 结论 | 只使用契约词 | 通过、不通过、人工阻塞、已停止、已取消、基础设施异常 |
| 不确定 | 明说缺什么 | 证据不足：缺少 3 个用例的串口日志 |
| 错误 | 发生了什么 + 影响 + 下一步 | 事件流已断开，正在每 5 秒轮询。数据可能滞后 5 秒。 |
| 危险操作 | 说明不可逆点 | 停止后当前执行将终止，已产生的证据会保留。 |
| 禁用 | 说明原因与所需角色 | 需要角色 4 才能切换全局模型。 |

禁止：

- 把“任务结束”写成“任务完成”。只有 C1 至 C7 全过并归档，才可使用“完成”。
- 用“AI 认为”替代证据。所有模型判断必须标注为“建议”并附引用。
- 用感叹号、庆祝动画、彩色纸屑表达 PASS。
- 在 UI 中出现 `DONE`、`SUCCESS` 等与终端状态契约冲突的词。

### 1.6 术语表

| 术语 | UI 文案 | 含义 |
|---|---|---|
| Task | 任务 | 一次需求受理到归档的完整对象 |
| Execution | 执行 | 一次真实运行，有独立 receipt |
| Plan revision | 计划修订 | 冻结后不可变的计划版本 |
| Gate | 门禁 | C1 至 C7 的二进制完成条件 |
| Verdict | 结论 | PASS / FAIL / BLOCKED_HUMAN / CANCELLED / STOPPED / INFRA_ERROR |
| Evidence | 证据 | 串口日志、音频、tool.log、results.csv、截图与哈希 |
| Playbook | 任务手册 | 完成后的可复用测试方法 |
| Binding | 模型绑定 | 不可变对象，含来源、候选链、版本 |
| Takeover | 接管 | 对执行会话的观察或交互控制 |
| Drift | 版本漂移 | 已安装版本与锁定版本不一致 |

## 2. 设计原则

### P1. 证据先于结论

任何“通过/不通过”旁边必须能到达证据与门禁。结论不是一个大号彩色徽章，而是一条可展开的证据链。

- 设计后果：任务详情顶部永远同时出现阶段、门禁、结论；结论徽章可点击跳到“门禁”页签。
- 反模式：只在列表里放一个苔绿 PASS，没有证据计数与门禁摘要。

### P2. 门禁永远可见

C1 至 C7 不是隐藏在详情里的调试信息。总览、任务列表、任务详情三处都必须能看到门禁摘要。

- 设计后果：门禁印列是共享组件；未通过的门禁在列表行内以 `C5` 小方块标出。
- 反模式：用一根 80% 的进度条暗示“快完成了”，但实际 C5 未通过。

### P3. 人是最终决定者

系统可以建议、排序、生成，但不能替人批准高风险计划或伪造结论。所有人类决策使用赭石信号，并记录 actor 与时间。

- 设计后果：等待人工的任务在总览有独立队列；批准按钮旁始终显示风险等级与批准人。
- 反模式：自动批准按钮默认勾选；用倒计时逼人确认。

### P4. 一屏一判断

每个页面的第一屏只回答一个问题。总览回答“平台是否健康”，任务列表回答“哪个任务需要我”，模型页回答“现在用的是什么模型”。

- 设计后果：页面顶部是结论式标题 + 一个主动作；细节下沉。
- 反模式：首屏塞满 12 个同权重指标卡。

### P5. 真实优于漂亮

所有“真实执行”标记必须来自 receipt、lease、manifest。原型中的 mock 数据必须明确标注。UI 不得用动画或文案暗示一个未发生的执行。

- 设计后果：`run_mode` 为 dry_run/replay 时，执行页签显示墨灰“预演，不可作为完成证据”横幅。
- 反模式：用苔绿勾表示“已执行”，但没有 node receipt。

### P6. 密度有呼吸

工程师需要密度，但密度不等于拥挤。用分组、留白与细线组织信息，而不是缩小所有字号。

- 设计后果：桌面基础字号 13px，表格行高 40 至 44px，区块间距 32 至 40px；卡片内边距 20px。
- 反模式：把 12px 当正文，用 8px 字重的标签堆满屏幕。

### P7. 可追溯

每个数字、徽章、结论都能回到来源：任务、事件 seq、证据哈希、知识引用、模型绑定 ID。

- 设计后果：ID/哈希使用等宽字体并可一键复制；知识引用使用 `[kb:...@rev#chunk]` 格式。
- 反模式：展示“92% 置信度”却没有定义与来源。

## 3. 视觉语言

### 3.1 隐喻：航次档案

页面不是“卡片瀑布”，而是一本持续装订的航次档案：

- **纸面**：暖白纸 `#F4F0E6`；每 48px 一条 3% 墨色横纹，只在页面边缘可见，不进入卡片。
- **页边**：左侧留出 20px 的装订边，时间戳、任务 ID、租约编号写在页边，不抢正文。
- **航向**：海青 `#1F5F5B` 用于当前可操作路径、运行中与链接。
- **批注**：朱砂 `#B8482C` 只标记人类注意点、审批与接管。
- **证据钉**：海玻璃绿 `#2C7A6B` 标记已核验的哈希、receipt、冻结计划。

背景实现建议（CSS，无图片）：

```css
body {
  background:
    linear-gradient(90deg, rgba(27,42,46,0.035) 0 1px, transparent 1px),
    repeating-linear-gradient(180deg, rgba(27,42,46,0.030) 0 1px, transparent 1px 48px),
    #F4F0E6;
  background-size: 100% 100%, 100% 48px, auto;
}
```

### 3.2 材质

| 层级 | 表面 | 边框 | 用途 |
|---|---|---|---|
| L0 画布 | `#F4F0E6` + 3% 横纹 | 无 | 页面底、装订边 |
| L1 面板 | `#F8F5EC` | `1px rgba(27,42,46,0.12)` | 命令甲板、状态缎带、分组容器 |
| L2 卡片 | `#FCFAF4` + 2px 偏移印刷阴影 | `1px rgba(27,42,46,0.20)` | 任务卡、指标、知识卡、档案页 |
| L3 浮层 | `#FFFDF8` | `1px rgba(27,42,46,0.38)` + 40px 投影 | 抽屉、弹窗、命令面板 |
| L4 终端 | `#12211F` + 内阴影 | `1px rgba(231,227,214,0.14)` | 接管、日志、机器输出 |

规则：

- 卡片圆角 4px，紧凑控件 3px，标签胶囊 999px。**不使用 12px 以上的大圆角卡片。**
- 卡片使用 2px 偏移的印刷阴影，不使用大面积柔光投影；hover 只改变边框与纸面亮度，不缩放。
- 仅弹层、命令面板与终端使用浮起材质；主界面保持平铺纸面，保证长时间阅读稳定。
- 不使用玻璃拟态堆叠、彩虹渐变、发光描边、彩色侧边条。

### 3.3 色彩故事

比例控制：纸面与墨色 82%，海青 10%，朱砂 4%，证据绿 2%，状态色 2%。

- **海青**：航向与可操作。主按钮、链接、运行中、选中。
- **朱砂**：人类。等待批准、等待接管、人工阻塞、审批批注。
- **海玻璃绿**：已核验。证据哈希、receipt 验签、归档完成。
- **氧化红**：失败与危险。FAIL、删除、停止确认。
- **深墨中性**：未决、禁用、陈旧。陈旧使用 `#647372` + 虚线/斜纹。

禁止：紫色渐变、彩虹数据系列、氧化红作为普通强调、海青表示“已通过”。

### 3.4 布局语法

- **顶部状态缎带 + 双行命令甲板 + 单一滚动主区**。桌面没有常驻左侧导航栏；导航是第二行横向索引。
- **12 列网格**，间距 20px，内容最大宽度 1560px，桌面边距 36px。
- **不对称档案跨页**：总览使用 1.6:1 的主副布局；任务详情使用 1fr + 300px 右侧 folio；不做三张等宽功能卡。
- **表格优先**：任务、证据、模型候选、版本矩阵、Agent 注册表都用表格，不用卡片堆叠替代。
- **列表行内结论**：每一行都能看到阶段、门禁、结论、证据数、模型来源。
- **首屏一个主动作**：新建任务、批准计划、切换模型、创建订阅等。

### 3.5 签名组件

1. **门禁印列 Gate Stamp Row**：七枚离散印章，C1 至 C7；每枚有通过/失败/待定/阻塞/不适用；点击展开证据引用。印章是方形，不是圆点，也不是连续进度。
2. **潮位尺 Voyage Ruler**：阶段进度，带 7 个刻度和当前阶段指针；与门禁印列并排，但语义不同。
3. **决断页边 Decision Margin**：右侧窄列，像档案页边的批注区；等待人工的事项按时长排列，朱砂细线只出现在这一列。
4. **证据结 Evidence Knot**：哈希链用一条折线和结点表示；每个结点可复制、可跳转到原始文件。
5. **模型绑定徽章 Binding Badge**：`G/A/T` 来源字母 + 模型短名 + 健康点；hover 显示完整 binding ID 与候选链。
6. **版本漂移徽章 Drift Badge**：`已安装 1.14.2 → 锁定 1.15.0`，纸色底 + 赭石点；点击跳到工具链页。
7. **接管终端 Takeover Terminal**：深墨绿台面、等宽、无大圆角；observe 模式输入框禁用并显示“只读观察”。

### 3.6 密度与字号

- 桌面正文 13px / 20px；阅读型段落 14px / 22px；表格 12 至 13px。
- 中文不使用 10px 作为正文；10px 只用于英文全大写眉标。
- 页面标题、关键数字、品牌字使用档案体（Sitka Banner）；控件与正文使用 Aptos / Segoe UI。
- 数字使用 `tabular-nums`，时长与哈希右对齐。
- 表格行高 40px（紧凑 36px，舒适 44px）；移动端列表项至少 64px。
- 卡片内边距 20px；紧凑卡片 16px；页面区块间距 44px。

### 3.7 图标

- 1.5px 描边、圆角端点、24 网格；尺寸 14/16/18/20/24。
- 使用内联 SVG，路径自绘；不引 CDN，不使用图标字体。
- 图标不单独承载状态：状态点必须配文字或 `aria-label`。
- 导航不使用图标堆叠；每个一级入口前是两位数字索引（01 至 11），数字使用等宽 9px。

### 3.8 插画与空状态

- 只使用 CSS/SVG 线稿，不使用图库照片、3D 渲染、AI 生成图。
- 空状态图形复用 ark 的节点链语言：一条未闭合的船底线、三枚未点亮的门禁印、一个空的页边批注位。
- 空状态必须包含：发生了什么、为什么、下一步按钮；不能只放一句“暂无数据”。

### 3.9 反模式清单

| 禁止 | 原因 | 替代 |
|---|---|---|
| 卡片左侧 3px 彩色条 | AI slop，且把状态压缩成一条颜色 | 状态徽章 + 门禁印列 + 底色微染 |
| 圆角卡片外加 2px 品牌色描边 | 同上，且与 focus 环混淆 | 选中用底色 + 勾选图标 |
| 紫色渐变背景/按钮 | 通用 AI 味 | 纸面 + 单一海青航向色 |
| 三张同构功能卡 | 没有信息层级 | 不对称档案跨页 + 表格/列表 |
| emoji 图标 | 跨平台不一致，不专业 | 内联 SVG |
| 全屏庆祝动画 | 与“证据驱动”语气冲突 | 结论徽章 + 证据摘要 + 轻微状态过渡 |
| 骨架屏长时间闪烁 | 让界面显得不稳定 | 首屏 200ms 内显示结构骨架，超过 1s 显示文字进度 |
| 隐藏 PASS 前提 | 可能造成误判 | 结论旁固定显示门禁摘要 |
| 用“完成”代替“通过” | 违反完成契约 | 使用契约词 |
| 自动轮播/自动刷新无提示 | 用户不知道数据何时变 | 显式“实时/降级”指示 + 更新时间 |

## 7. 共享组件

所有组件必须提供：默认、hover、focus-visible、active、disabled、loading、error、empty（适用时）。状态不能只靠颜色。

### 7.1 应用外壳 App Shell

结构：

```
┌──────────────────────────────────────────────────────────────┐
│ 状态缎带 26：环境 · 构建 · 最后事件 · 实时 · 角色 · 用户      │
├──────────────────────────────────────────────────────────────┤
│ 命令甲板 52：ark NoahsArk     搜索     实时  用户  [新建任务]│
│ 导航行 38：01 总览 02 任务 03 思考 04 知识 05 节点 … 11 系统 │
├──────────────────────────────────────────────────────────────┤
│ 上下文条 36（仅详情页）：任务 / <id> / 证据 · 状态 · 返回     │
├──────────────────────────────────────────────────────────────┤
│ 主区（唯一滚动）                                             │
│   页面头 / 档案跨页 / 表格 / folio                           │
└──────────────────────────────────────────────────────────────┘
```

规则：

- `display: grid; grid-template-rows: var(--ribbon) var(--deck) minmax(0,1fr); block-size: 100dvh;`
- 主区 `min-block-size: 0; overflow: auto;`，这是滚动生效的关键。
- 缎带与命令甲板作为 grid 固定行，不使用 `position: fixed` 叠加；主区页面头可 sticky，但 `top: 0` 相对主区滚动容器。
- 没有常驻左侧导航栏；桌面、平板、手机使用同一 DOM 顺序（缎带 → 甲板 → 上下文条 → 主区）。
- 移动端导航 sheet 使用 `dialog`，焦点陷阱，Esc 关闭，关闭后焦点回到菜单按钮。
- 接管模式隐藏缎带、甲板与底部导航，只保留终端与状态带。

### 7.2 页面头 Page Header

元素：眉标（英文大写 + 日期/上下文）、标题（20 至 24px）、一句话状态、主操作、次操作、面包屑。

- 标题使用结论式语言，例如“3 个任务在航，1 个等待你决断”，而不是“欢迎回来”。
- 主操作最多 1 个实底按钮；次操作使用 ghost。
- 危险操作不放在主操作位；放在右侧“更多”菜单并二次确认。
- 移动端标题 20px，操作收进“更多”或底部固定条。

### 7.3 卡片 Card

- 表面 `--na-paper-card`，1px `--na-border`，圆角 4，内边距 20。
- 阴影使用 2px 偏移印刷阴影，不使用顶部内高光或柔光。
- hover：背景到 `--na-paper-card-hover`，边框到 `--na-border-strong`；不缩放、不位移超过 1px。
- 可点击卡片必须有 `role`/`tabindex` 与 focus ring；内部按钮点击不得触发卡片导航。
- 禁止左侧色条、彩色描边、渐变描边、彩色外环。

### 7.4 状态徽章 Status Badge

结构：`[状态点 6px] [文字 12px] [可选计数]`。背景为状态色 10% 透明，文字为状态 ink 色，边框 1px 状态色 24%。

| 状态 | 文案 | 颜色 | 说明 |
|---|---|---|---|
| running | 执行中 | 海青 | 附当前阶段 |
| waiting | 等待人工 | 朱砂 | 附等待时长 |
| pass | 通过 | 苔绿 | 必须同时显示门禁 7/7 |
| fail | 不通过 | 氧化红 | 附根因类别 |
| blocked | 人工阻塞 | 朱砂 | 非终态 |
| stopped | 已停止 | 墨灰 | 保留证据 |
| cancelled | 已取消 | 墨灰 | 无结论 |
| infra | 基础设施异常 | 氧化红 | 非产品结论 |
| stale | 已陈旧 | 墨灰 + 虚线 | 知识/版本 |
| disputed | 有争议 | 赭石 | 知识 |
| disabled | 已禁用 | 墨灰 | 订阅/开关 |

规则：颜色不是唯一信号；文字必须出现。计数使用 `tabular-nums`。

### 7.5 门禁印列 Gate Stamp Row

结构：7 个节点（C1 至 C7）水平排列，节点之间 1px 连接线；每个节点上方是 `C1` 等宽标签，下方是短状态词（通过/失败/待定/阻塞/不适用）。

交互：

- hover/focus 显示 tooltip：门禁名称、二进制要求、证据引用、最后评估时间。
- 点击节点打开“门禁”页签或侧滑详情，定位到该门禁。
- 键盘：左右方向键在节点间移动，Enter 打开详情。
- 通过：实心苔绿印章 + 勾；失败：氧化红印章 + 叉；待定：空心墨线印章；阻塞：朱砂印章 + 暂停；不适用：斜线填充。
- 不允许把 7 个门禁压成一根百分比进度条。

尺寸：桌面印章 18px，连接线 1px；手机印章 14px，标签仅显示 `C1`，状态在下方图例中展开。

### 7.6 潮位尺 Voyage Ruler

- 用于阶段（受理 → 检索 → 计划 → 审批 → 预检 → 执行 → 归档），不是门禁。
- 轨道 3px，填充 3px；7 个刻度；当前阶段用 1px 竖线指针标记。
- 运行中允许 2.2s 的轻微扫光；减少动态时静止。
- 必须显示文字阶段名与百分比（百分比只描述阶段，不描述完成度）。
- 失败/阻塞时轨道停在对应阶段，颜色变为状态色，但不用氧化红铺满整条。

### 7.7 表格 Data Table

- 表头 11px 大写英文或 12px 中文，`--na-text-tertiary`，背景 `--na-ink-300`。
- 行高 40 至 44px；单元格 14/12px；数字右对齐；ID/哈希等宽。
- 行 hover 使用 `--na-brand-wash`，不改变文字颜色。
- 选中行使用 `--na-brand-soft` 底 + 行首勾选标记；不使用左侧品牌线。
- 排序：表头按钮带 `aria-sort`；当前排序图标常显。
- 空表：保留表头 + 一行空状态，不显示“暂无数据”四个字就结束。
- 手机：表格变为定义列表卡片；每张卡保留主键、状态、两个关键指标、操作。禁止横向滚动整个页面；允许表格容器内横向滚动并显示滚动提示。

### 7.8 时间线 Timeline

- 用于执行阶段、事件、审计、升级历史。
- 左侧 1px 轨道，节点 8px；时间戳等宽、右对齐或置于上方。
- 事件类型有图标 + 文字；严重级别用状态色点，不用整行染色。
- 长列表虚拟化；默认显示最近 50 条，提供“加载更早”。
- 实时追加时，若用户不在底部，显示“有 3 条新事件”按钮，不强行滚动。

### 7.9 证据列表 Evidence List

每条证据显示：类型图标、文件名、用例 ID、大小、哈希前 12 位、生成时间、验签状态、下载。

- 证据按用例分组，默认折叠为“3 个用例 · 14 个文件 · 86 MB”。
- 缺失证据用赭石“缺少”行，列出 required kind 与阻塞门禁 C5。
- 空捕获（0 字节/无标记）显示氧化红“无效证据”，不可下载为通过依据。
- 下载按钮调用受控 API，审计记录 actor、task、file；不直接暴露文件系统路径。
- 哈希点击复制完整值，toast 显示“已复制 SHA-256”。

### 7.10 模型绑定徽章 Model Binding Badge

结构：`[G|A|T] [模型短名] [健康点]`。

- 来源：G 全局、A Agent、T 任务覆盖；字母使用等宽 10px，背景对应来源色（G 中性、A 蓝、T 赭石）。
- 模型短名最多 18 字符，超出省略；hover/focus 显示完整 provider/model、binding_id、resolution_source、候选链、catalog_version。
- 健康点：苔绿 healthy、赭石 degraded、氧化红 blocked、墨灰 stale。
- 切换后显示“下一轮生效”小标签，直到新绑定被实际使用。
- 禁止显示 provider 密钥、base URL、原始请求。

### 7.11 版本漂移徽章 Version Drift Badge

结构：`[!] 已安装 1.14.2 → 锁定 1.15.0`。

- 默认中性底；漂移时赭石点 + “漂移”；不兼容时氧化氧化红点 + “不兼容”。
- 点击进入工具链页并定位到该组件。
- 真实执行受影响时，在执行按钮旁显示阻断说明，而不是只藏在系统页。

### 7.12 接管终端 Takeover Terminal

- 使用本地打包的 xterm（无 CDN）；容器 `--na-overlay-terminal`，内阴影，无圆角或 8px 圆角。
- 顶部状态带：模式（观察/交互/已暂停）、控制者、租约 epoch、剩余空闲时间、连接状态。
- 底部输入区：多行文本框、发送、中断、释放；observe 模式输入禁用并显示“只读观察”。
- 回放与实时之间有明显分隔线“以上为历史回放”。
- 终端输出必须提供“复制为文本”和“下载日志”；屏幕阅读器用户可使用“文本日志”页签。
- 禁止显示密钥、tool 参数中的敏感值；服务端已脱敏，前端仍需避免回显。
- 断线时终端覆盖层显示“连接中断，正在重连（第 n 次）”，输入禁用，任务不受影响。

### 7.13 空 / 错误 / 加载状态

| 状态 | 结构 | 文案示例 |
|---|---|---|
| Loading | 结构骨架（不超过 3 个块）+ 文字“正在加载任务投影” | 超过 1s 显示进度说明；超过 10s 显示“仍在等待服务端” |
| Empty | 线稿图形 + 标题 + 解释 + 主动作 | “还没有任务。从一条需求开始，平台会先检索相似任务。” |
| Error | 图标 + 发生了什么 + 影响 + 重试 + 请求 ID | “任务投影加载失败。当前显示的是 30 秒前的缓存。重试 / 复制请求 ID” |
| Blocked | 赭石横幅 + 阻塞原因 + 解除条件 + 责任人 | “等待人工批准：B 类高风险计划。批准后可进入预检。” |
| Stale | 灰 + 虚线 + 最后更新时间 + 刷新 | “数据已陈旧 6 分钟。SSE 已降级为轮询。” |
| Disabled | 降低透明度 + 锁/信息图标 + 原因 | “需要角色 4 才能切换全局模型。” |

错误必须保留用户输入；重试不得清空筛选或表单。

### 7.14 提示与 Toast

- 成功：苔苔绿点 + 一句话 + 可选“查看”；2.4s 自动消失。
- 失败：氧化氧化红点 + 原因 + 重试；不自动消失，需手动关闭。
- 警告：赭石点 + 说明；4s。
- 位置：桌面右下，手机底部（避开底部导航）。
- `aria-live="polite"`；错误使用 `role="alert"`。
- 同一条消息不重复堆叠，合并为“3 条事件已更新”。

### 7.15 页签 Tabs

- 任务详情 11 个页签，横向排列；桌面可换行，平板/手机横向滚动。
- 结构：`role="tablist"`，每个 tab `role="tab"`，面板 `role="tabpanel"`；左右方向键切换，Home/End 到首尾。
- 当前 tab：`--na-brand-soft` 底 + 文字主色 + 4px 方形标记；不使用底部强调线；未选中 `--na-text-tertiary`。
- 页签带计数时使用 10px 等宽，例如“证据 14”。
- 页签内容切换不改变滚动位置，除非显式“查看门禁”跳转。

### 7.16 筛选栏 Filter Bar

- 搜索输入 + 3 至 5 个下拉 + 已选条件 chips + 清除。
- 筛选即时生效（300ms 防抖），但 URL 同步；不弹“应用”按钮，除非筛选项超过 8 个。
- 已选条件以胶囊展示，可单个移除；“清除全部”在末尾。
- 手机：筛选收进底部抽屉，顶部只显示搜索与“筛选 3”。

### 7.17 抽屉与弹窗

- 抽屉：右侧 420 至 560px，用于详情、创建订阅、模型切换确认；遮罩点击关闭，Esc 关闭。
- 弹窗：仅用于不可逆确认、权限升级、危险操作；宽度 440 至 560px。
- 焦点陷阱；打开时焦点到标题或第一个输入；关闭后回到触发元素。
- 危险确认按钮文字必须是动词，例如“停止任务”，不是“确定”。

### 7.18 命令面板 Command Palette

- `Ctrl/Cmd + K` 打开；输入即搜索页面、任务 ID、知识标题、节点、模型。
- 分组：跳转、任务、知识、操作；每组最多 5 条。
- 支持 `>` 进入命令模式，例如 `> 新建任务`、`> 切换全局模型`。
- 键盘上下选择，Enter 执行，Esc 关闭；无结果时给出“搜索知识库”与“新建任务”两个出口。
- 不显示无权限命令，或显示但标注“需要角色 4”。

### 7.19 知识结果卡 Knowledge Result

结构：状态徽章 + 类型 + 标题 + 匹配理由 + 适用性 + 差异/警告 + 引用 + 操作。

- 匹配理由用 `why_matched` 的真实字段，例如“设备类别相同”“标签 wake”。
- 适用性显示 lstest pin、固件、范围；不适用时明确“差异：固件不同”。
- 陈旧/争议必须在标题行可见，不能只靠详情。
- “应用到计划”只创建草案修订，需审计与再次审批；按钮旁说明。

### 7.20 任务行 / 任务卡

列表行：任务标题 + ID、项目/设备、阶段、门禁摘要、结论、证据数、模型徽章、更新时间。

- 标题两行截断；ID 等宽 11px。
- 门禁摘要显示 7 个小方块；失败门禁优先。
- 行内不放大段描述；需求摘要最多 1 行。
- 手机卡：标题、状态、阶段、门禁、时间、主操作。

### 7.21 指标条 Metric Strip

- 不是 4 张同构卡片；是一条横向仪表带，指标之间 1px 分隔线。
- 每个指标：标签 11px 大写/中文、数值 24 至 32px 等宽、变化说明、可选迷你趋势。
- 最多 5 个指标；超过则分组。
- 数字必须有单位与时间窗口，例如“今日通过 12 / 14”。

### 7.22 可复制 ID / 哈希

- 等宽 11 至 12px，默认显示前 12 位，hover 显示完整。
- 点击复制；复制成功 toast；提供 `aria-label="复制任务 ID"`。
- 不换行；容器 `overflow-wrap: anywhere` 仅在详情展示完整值时使用。

### 7.23 权限门 Permission Gate

- 不隐藏不可执行按钮，而是 disabled + 原因。
- 原因通过 `aria-describedby` 与可见的小字同时表达。
- 角色不足时提供“查看权限说明”，不提供“申请”假入口（除非后端有审批流）。

### 7.24 实时连接指示 Live Indicator

- 命令栏：点 + 文案（实时/降级轮询/离线）+ 最后事件时间。
- 降级时页面顶部出现 1px 赭石线；离线时氧化红线。
- 禁止仅仅用一个苔绿点表示实时；颜色 + 文字 + `aria-live` 文本。

│                                                      │ 复现哈希               │
│                                                      │ 负责人 / 审批人        │
└──────────────────────────────────────────────────────┴───────────────────────┘
```

- 顶部任务头 sticky 于主区顶部；页签条 sticky 在任务头下方；内容滚动。
- 任务头高度约 150px（含航程与门禁）；手机上压缩为 2 行 + 可展开。
- 右侧上下文栏只在桌面显示；平板下沉到内容底部；手机用“上下文”折叠面板。
- 页签内容最大宽度不限，但正文段落限制 72ch。

#### 顶部任务头

- 标题：需求标题，最多 2 行；ID 等宽 11px，可复制。
- 状态徽章：结论优先；无结论显示阶段。
- 主操作随状态变化：
  - 待批准：`批准计划`（主）、`请求修改`（次）。
  - 已批准待预检：`开始预检`。
  - 执行中：`暂停`（次）、`停止`（危险，更多菜单）、`接管`。
  - 等待人工：`进入接管`（主）、`批准继续`（若有）。
  - 终态：`导出交付`（主）、`查看知识`（次）、`重新运行`（更多）。
- 元信息行：项目、设备、节点、模型徽章、创建者、更新时间、风险等级、运行模式（真实/预演）。
- 潮位尺：7 阶段；当前阶段有外环；失败阶段变红但保留后续灰。
- 门禁印列：7 节点；点击跳到门禁页签并展开对应项。
- 门禁说明：一行“C2 等待真实执行”“C5 缺少 3 个用例证据”，使用状态色文字，不用整条横幅。

#### 页签：概要 Summary

内容：

1. **需求摘要**：2 至 4 句，来自需求解析；每句带来源引用 `[需求:文件#章节]`。
2. **澄清记录**：问题、回答、回答人、时间；未回答的问题用赭石“待确认”。
3. **风险与范围**：风险等级 A/B、影响设备、样本量、禁止项、删除/无效需求项。
4. **关键事实**：项目、芯片、固件、语言、端口、音频端点、能力范围。
5. **当前判断**：平台建议下一步 + 依据；不把建议写成结论。
6. **最近事件**：5 条时间线。

主要操作：`编辑澄清`（3/4，生成新计划修订）、`查看相似任务`、`复制需求哈希`。

#### 页签：计划 Plan

内容：

1. 计划修订选择器：`rev 3 · 已冻结`、`rev 2 · 已被替换`；冻结后只读。
2. 计划摘要：目标、范围、前置条件、环境、样本量、通过标准、回滚。
3. 覆盖率矩阵：需求点 × 用例 × oracle，显示 100% / 缺口。
4. 对抗评审发现：严重级别、发现、证据、建议修复、解决状态（已修改/豁免/未解决）。
5. 保证门禁：traceability、oracle 可证伪、证据绑定、profile 编译、预检 fixture。
6. 审批记录：actor、时间、范围、批准 ID；B 类必须人工。

操作：`请求修改`、`批准计划`（有权限且 assurance 通过）、`导出计划 JSON`、`比较修订`。

#### 页签：用例 Cases

- 表头：用例 ID、标题、需求引用、oracle 类型、证据要求、重试、状态。
- 行展开：前置条件、动作、期望、禁止项、证据窗口、断言、证据目录。
- 筛选：全部/通过/失败/阻塞/未执行；按 oracle 类型筛选。
- 批量：无批量执行；可“复制用例 ID”。
- 空：计划尚未生成用例时显示“计划批准后生成用例”与“查看计划”。

#### 页签：执行 Execute

1. **运行摘要**：run_mode（真实/预演）、execution_id、节点、租约、开始/结束、runner exit。
2. **预检**：10/20 次预检进度、通过次数、失败原因、最后一次预检输出。预检未通过时“开始执行”禁用。
3. **阶段时间线**：构建、部署、执行、采集、自愈、验证；每步耗时与结果。
4. **自愈记录**：问题、根因分类、修复、验证结果、是否影响结论；最多 5 条，展开更多。
5. **实时日志**：最近 200 行，等宽；暂停自动滚动；跳到底部。
6. **执行 receipt**：节点签名、lease id、端点身份、artifact manifest hash；未验证时显示“未验签”。

操作：`开始预检`、`开始执行`（仅批准且预检通过）、`暂停`、`停止`、`接管`、`下载执行日志`。

#### 页签：证据 Evidence

- 顶部统计：用例数、文件数、总大小、缺失项、验签状态。
- 证据树：按用例分组；每条：类型、文件名、大小、哈希、时间、验签、下载。
- 缺失证据：赭石行，列出 required kind 与阻塞门禁；提供“重新采集”（若可重跑）。
- 预览：右侧抽屉显示文本/图片/音频元数据；不自动播放音频。
- 无效证据：0 字节、空捕获、哈希不匹配，氧化红标记，禁止作为通过依据。

操作：`下载全部清单`、`复制哈希`、`重新采集`（3/4，需确认）、`导出证据索引`。

#### 页签：结论 Verdict

1. 大号结论：通过/不通过/人工阻塞/已停止/已取消/基础设施异常；旁边显示“机器结论”与“人工结论”两个来源。
2. 四个维度：功能、稳定性、性能、证据充分性；每项状态与说明。
3. 机器复算：runner 结论 vs 复算结论；分歧时氧化红“VERDICT_DIVERGENCE”与阻断说明。
4. 根因分类：14 类树中的最终类别；FAIL 仅允许 firmware/requirement；其他类别显示“已收敛为测试/环境问题，不作为产品 FAIL”。
5. 业务/人工策略：人工覆盖记录、actor、时间、理由；机器结论不可被覆盖，只能附加人工结论。
6. 结论依据：每条结论对应证据与门禁引用。

操作：`导出结论报告`、`查看门禁`、`发起争议`（4，记录理由）。

#### 页签：门禁 Gates

- 7 行，每行：C1 至 C7、名称、二进制要求、状态、证据引用、评估时间、阻断说明。
- 展开：原始 evidence 引用、hash、gate report id、失败原因。
- 顶部：completion report hash、eligible 状态、最后评估、报告版本。
- 底部：`重新评估门禁`（4，审计）、`下载门禁报告`。
- 规则：终态但 report 缺失时显示氧化红“完成契约违规”，不允许导出“通过”交付。

#### 页签：知识 Knowledge

- 写回状态：playbook 已创建/待创建、failure candidates 数、script fixes 数、`no_reusable_knowledge` 原因。
- playbook 卡：requirement signature、plan/case/oracle 哈希、前置条件、证据要求、失败模式、结果、复用标签。
- failure 卡：症状、根因、证据、去重签名、状态。
- script fix 卡：工具/技能、diff 摘要、症状、修复、证据、评审状态。
- 操作：`查看知识详情`、`提交候选`（系统自动，人工可补充）、`标记不可复用`（需理由，3/4）。

#### 页签：相似 Similar

- 检索包摘要：query、top-5、是否 `no_history`、检索耗时。
- 每条：类型、标题、状态、score、why_matched、适用性（lstest pin/固件/范围）、可复用块、差异、警告、引用。
- 操作：`应用块到计划`（创建草案修订，审计，需重新审批）、`查看来源任务`、`标记不相关`（反馈）。
- 规则：stale/disputed 不得静默排在 approved 前；差异与警告必须在卡片上可见。

#### 页签：接管 Takeover

- 会话卡：target_kind（lead/workunit/node）、CLI 类型与版本、native session id、模型绑定、状态、resume cursor、最后活动。
- 租约卡：lease_epoch、控制者、模式、获取时间、空闲超时、自动释放时间。
- 观察/交互切换：角色 2 只能观察；角色 3 自己任务可交互；角色 4 任意。
- 最近接管事件：acquire、pause、input、release、timeout、conflict。
- 主操作：`进入接管终端`；`释放控制`（若持有）。
- 规则：终态任务不可接管；租约冲突显示 409 文案与当前控制者。

#### 页签：日志 Logs

- 事件流：seq、时间、类型、severity、payload 摘要；支持按类型/级别/关键词筛选。
- 默认显示最近 100 条；提供“加载更早”和“跳转到最新”。
- SSE 实时追加；用户不在底部时显示“有 N 条新事件”。
- 操作：`下载 NDJSON`、`复制事件 ID`、`打开原始 JSON`（脱敏后）。
- 规则：不显示 authorization、cookie、token、provider key；payload 中的敏感字段显示 `[redacted]`。

#### 右侧上下文栏（桌面）

1. **模型绑定**：角色列表（lead/planner/case_writer/script_implementer/reviewer），每条显示模型徽章、来源、健康、下一轮生效。
2. **设备租约**：节点、设备、串口、音频端点、lease id、到期时间。
3. **工具链 pin**：opencode、OMO、lstest、平台 commit；漂移徽章。
4. **复现清单**：repro hash、模型绑定 ID 列表、环境指纹；复制。
5. **人员**：创建者、审批人、接管人、知识负责人。
6. **快捷链接**：相似任务、知识、交付、审计。

#### 状态

| 状态 | 表现 |
|---|---|
| 加载 | 任务头骨架 + 页签骨架；不显示空结论；超过 1s 显示“正在加载任务投影” |
| 空 | 任务 ID 不存在：404 页面“任务不存在或已被归档”；提供返回列表与搜索 |
| 错误 | 任务头保留上次缓存；内容区错误卡“页签加载失败”；重试；请求 ID |
| 阻塞 | 顶部朱砂状态 + “等待人工批准”；主操作“批准计划”；执行页签锁定并解释 |
| 陈旧 | 页签内容上方“最后更新 2 分钟前”；SSE 降级时显示轮询提示；不隐藏数据 |
| 禁用 | 未满足门禁的开始执行、未授权接管、冻结计划的编辑均禁用并解释 |

#### 进度

- 潮位尺 + 门禁印列双轨；百分比只用于阶段。
- 运行中在阶段条上有 1.8s 扫光；减少动态时静止。
- 证据页签显示采集进度“14/18 文件已验签”。

- **手机 390**：
  - 任务头：标题 18px、状态、ID、主操作；潮位尺横向滚动；门禁印列折叠为“门禁 5/7”按钮，点击展开。
  - 页签横向滚动，sticky 在任务头下方；当前 tab 自动可见。
  - 表格变卡片；证据树变折叠列表；日志全宽。
  - 危险操作放在底部 sheet，二次确认。
  - 接管页全屏，不显示底部导航。

#### 边界与规则

### 8.4 思考 / 受理台 Think

- **目标**：把一条模糊需求变成可批准、可预检、可执行的任务，而不是直接“开始跑”。
- **路由**：`/aitest/think`；可从 `/aitest/think?draft=<id>` 恢复草稿。
- **权限**：角色 3 至 4；角色 1 至 2 可查看示例与知识，但不可提交。
- **对应能力**：需求澄清、知识先行检索、风险分级、计划草案、预检清单、提交审批（P4-01 至 P4-06）。
- **设计意图**：四步纵向工作台，右侧始终显示“知识先行的证据”，而不是聊天窗口。

#### 布局（桌面 1440）

```

│ 步骤条：1 需求  2 澄清  3 检索  4 计划与预检   │ 知识先行（右侧 380px）        │

- 主工作区 1fr，右侧 380px；桌面右栏 sticky。
- 步骤条不是必须线性完成的向导：允许回看与修改，但“提交审批”要求 1 至 3 完成。
- 步骤 4 的计划摘要可展开为完整计划；默认显示 6 行关键信息。
- 底部固定操作条：`保存草稿`、`上一步`、`下一步`、`提交审批`。

#### 步骤与数据

**步骤 1：需求**

- 字段：任务标题（必填，8 至 80 字）、项目（必选）、设备（可选，后续可分配）、需求文本（必填，支持粘贴 Markdown）、附件（md/txt/pdf-text/docx/xlsx-text）、期望结果、样本量、禁止项。
- 自动解析预览：项目、芯片、固件、语言、端口、音频端点、能力范围、默认状态、动作、数值约束、删除/无效项。
- 风险初判：A 类（低风险、可自动批准）或 B 类（高风险、必须人工），显示判定依据。
- 规则：不把“未知”自动填成旧项目默认值；未知字段显示“待确认”。

**步骤 2：澄清**

- 平台生成问题，按影响排序；每条包含：问题、为什么影响结论、建议选项、自由回答、标记“未知”。
- 问题示例：“200 次唤醒的失败判定是单次未唤醒即失败，还是按 3 次窗口？”“TCL003 当前固件 0x2A1 是否为测试目标？”
- 已回答：显示回答、回答人、时间；可编辑（生成新草稿版本）。
- 未回答且阻塞：赭石“必须先回答”，提交审批禁用。
- 允许“跳过并记录风险”，但 B 类高风险不可跳过关键项。

**步骤 3：检索**

- 检索包：query（项目/设备/标签/文本）、top-5、`no_history` 标记、检索耗时、总命中。
- 每条命中：kind、标题、状态、score、why_matched、适用性、可复用块、差异、警告、引用。
- 无命中：显示“没有足够相似的历史”，提供“按工具知识库方法起草”和“创建全新方法”两个出口；不阻塞，但计划需更强评审。
- 操作：`应用块到计划`（勾选可复用块）、`查看来源`、`标记不相关`。

**步骤 4：计划与预检**

- 计划摘要：目标、范围、用例数、oracle 类型、样本量、预计时长、所需节点/设备、证据要求、回滚。
- 覆盖率：需求点 × 用例 × oracle；缺口用赭石。
- 保证门禁：traceability、oracle 可证伪、证据绑定、schema、profile 编译、lstest fixture 预检、readiness。
- 预检清单：10/20 次预检计划、设备在线、串口可打开、音频端点存在、工具链无漂移。
- 审批：A 类可自动（若策略允许），B 类显示“需要人工批准”与审批人；提交后任务进入“待批准”。
- 操作：`提交审批`（主）、`保存草案`、`请求圆桌评审`（打开圆桌并带入主题）。

#### 右侧“知识先行”栏

1. 检索包摘要：命中数、最高分、耗时、是否 no_history。
2. top-3 命中卡（可展开 top-5）：状态、为什么命中、可复用块、差异、警告。
3. 预检清单：每项状态（待检查/通过/失败）与来源。
4. 风险与审批：风险等级、判定依据、所需审批角色。
5. 草稿状态：最后保存、自动保存开关、版本。

#### 主要操作

| 操作 | 权限 | 行为 |
|---|---|---|
| 保存草稿 | 3 至 4 | 本地 + 服务端草稿，不创建任务 |
| 提交审批 | 3 至 4 | 创建任务 + 计划修订 + assurance；进入待批准 |
| 请求圆桌评审 | 3 至 4 | 预填 topic 与角色，跳转圆桌 |
| 应用复用块 | 3 至 4 | 创建计划草案修订，审计 |
| 放弃草稿 | 3 至 4 | 二次确认，删除草稿不删除已引用知识 |

#### 状态

| 状态 | 表现 |
|---|---|

#### 切换抽屉

- 标题“切换全局模型”；当前模型 → 目标模型。

- 确认按钮：`切换模型`；危险色不使用氧化红，因为可回滚；使用品牌实底。

| 状态 | 表现 |

| 阻塞 | `MODEL_BLOCKED`/配额用尽：氧化红横幅 + 受影响角色/任务 + 解决建议 |
| 陈旧 | catalog 超过 TTL：赭石“目录快照已过期，不可用于新绑定” |
| 禁用 | 角色不足的切换按钮；能力不满足的候选；stale 模型 |

#### 进度

- 验证/测试调用显示“进行中”与已用时间，不显示假百分比。
- 切换显示“已提交 → 下一轮生效”，直到实际使用后变为“已生效”。

| 状态 | 表现 |

| 加载 | 指标与表格骨架 |

### 8.14 接管 Takeover

- **目标**：在安全边界内观察或接管执行会话，回放历史、注入输入、释放控制。
- **路由**：`/aitest/tasks/<task_id>/takeover`
- **权限**：角色 2 观察；角色 3 交互自己任务；角色 4 任意；终态不可接管。
- **对应能力**：session registry、lease CAS、safe pause、history replay、input、release（P6-01 至 P6-06，P7-07）。
- **设计意图**：终端是主角，状态与边界必须比终端更醒目。

#### 布局（桌面 1440）

```
命令栏（全屏模式）：← 返回任务 | 接管 · ait-20261026-0412 | [交互中] | 控制者 陈工
┌──────────────────────────────────────────────┬──────────────────────────────┐
│ 状态带：模式 / 租约 epoch / 空闲倒计时 / 连接  │ 会话信息（300px）             │
│ 终端（xterm，占满剩余高度）                   │ 任务、目标、CLI、模型          │
│ > 历史回放 ...                                │ resume cursor                 │
│ ── 以上为历史，以下为实时 ──                  │ 最近接管事件                  │
│ > _                                           │ 审计提示                      │
├──────────────────────────────────────────────┴──────────────────────────────┤
│ 输入区：[多行输入] [发送] [中断当前轮] [释放控制]                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 全屏模式隐藏导航区与底部导航；命令栏保留返回。
- 终端高度 `calc(100dvh - 命令栏 - 状态带 - 输入区)`；输入区固定底部。
- 观察模式：输入区禁用，显示“只读观察”；可复制文本、下载日志。
- 交互模式：输入框可用；发送前显示“将注入同一原生会话”。
- 中断：单独按钮，需确认“当前轮会安全停止，不影响已确认设备动作”。

#### 区块与数据

1. **状态带**
   - 模式：观察/交互/已暂停/已释放。
   - 控制者：用户 + 角色；租约 epoch；空闲倒计时；连接状态（实时/重连中/断开）。
   - 安全提示：“设备动作仍经命令门面，重复 effect 会被拒绝。”
2. **终端**
   - 历史回放与实时分隔；回放游标；自动滚动开关。
   - 输出脱敏；工具参数中的密钥显示 `[redacted]`。
   - 提供“文本日志”页签，供屏幕阅读器与复制。
3. **会话信息**
   - 任务、target_kind、workunit、CLI kind/version、native session id（脱敏/可复制）、模型绑定、resume cursor、最后活动。
   - 最近接管事件：acquire/pause/input/release/timeout/conflict，含 actor 与时间。
4. **输入区**
   - 多行文本、发送、中断、释放；字符计数；Enter 发送/Shift+Enter 换行（可配置）。
   - 发送后显示“已注入，等待下一轮”；不假装立即有回复。
5. **冲突**
   - 409：显示当前控制者、epoch、获取时间；提供“观察”而不是抢占。

#### 主要操作

| 操作 | 权限 | 行为 |
|---|---|---|
| 获取观察 | 2 至 4 | 只读租约，不暂停 agent |
| 获取交互 | 3 自己/4 任意 | CAS 获取 epoch；agent 在 turn boundary 暂停 |
| 发送输入 | 交互控制者 | 注入同一 session；审计 |
| 中断当前轮 | 交互控制者 | 安全点停止，需确认 |
| 释放控制 | 控制者 | 恢复 agent，保留 checkpoint |
| 下载日志 | 2 至 4 | 脱敏文本/NDJSON |
| 复制终端文本 | 2 至 4 | 仅可见内容 |

#### 状态

| 状态 | 表现 |
|---|---|
| 加载 | 终端骨架 + “正在连接会话”；状态带“连接中” |
| 空 | 无会话：“该任务尚未启动执行会话”；返回任务 |
| 错误 | 连接失败：终端覆盖层“无法连接”；重试；任务不受影响 |
| 阻塞 | 租约冲突/任务终态/权限不足：状态带氧化红/赭石 + 原因；输入禁用 |
| 陈旧 | 重连中：显示“正在从 cursor 恢复”；不把旧输出当实时 |
| 禁用 | 观察模式输入；非控制者发送；终态接管 |

#### 进度

- 空闲倒计时（默认 30 分钟）显示为“剩余 27:14”；最后 5 分钟赭石。
- 不显示“接管完成度”。

#### 响应式

- 平板：会话信息下沉为可折叠；终端仍占主区。
- 手机：全屏终端；状态带两行；输入区固定底部；会话信息为底部 sheet；横屏建议提示“横屏获得更好终端体验”，但不强制。
- 手机不显示导航区；返回按钮 44px。

#### 边界与规则

- 接管不是 raw shell；不提供任意命令执行入口。
- 不在 UI 显示凭据、provider key、tool 参数敏感值。
- 释放后 agent 从 checkpoint 恢复；重复 effect key 被拒绝，UI 显示“已确认动作不会重放”。
- 断线不改变任务状态；输入在断线时禁用。

## 9. 交互流程

所有流程都遵循两条硬规则：

1. **不可逆动作必须有确认与审计**：停止、释放租约、撤回知识、关闭 V2、全局模型切换。
2. **UI 不得先于服务端事实**：按钮点击后进入 pending，只有收到命令结果或事件才改变结论；不做乐观的“已完成”。

### 9.1 任务主流程：受理 → 计划确认 → 预检 → 执行 → 自愈 → 结论 → 知识回写

| 步骤 | 触发 | UI 表现 | 系统事实 | 失败/分支 |
|---|---|---|---|---|
| 1 受理 | 在思考页填写需求并提交 | 保存草稿 → 创建任务 → 进入任务详情“概要”；状态“受理” | 生成 task_id、需求哈希、检索包 | 关键字段缺失 → `BLOCKED_HUMAN`，列出缺失字段 |
| 2 知识先行 | 任务创建后自动 | 相似页签出现 top-5；概要显示“已检索 5 条，2 条可直接复用” | `task_retrievals.packet_json`；`retrieval.completed` 事件 | 无命中 → `no_history` 包，计划需更强评审 |
| 3 澄清 | 平台生成问题 | 概要“待确认 3 项”；问题卡显示影响与建议 | 回答写入任务；缺失关键项阻塞 | 跳过关键项 → 必须记录风险，B 类不可跳过 |
| 4 计划 | 平台生成 `test_plan.v2` | 计划页签显示覆盖率、oracle、保证门禁、评审发现 | 计划修订、哈希、assurance 报告 | 覆盖率缺口/评审 blocking → 批准禁用 |
| 5 计划确认 | 人点击“批准计划” | 确认抽屉：风险、门禁、评审发现、审批人 | 冻结计划修订；写入 approval_id | 无权限/有 blocking → 禁用并解释；B 类必须人工 |
| 6 预检 | 点击“开始预检” | 执行页签显示 10/20 次进度、失败项、最后一次输出 | dry-run 仅预检，不产生完成证据 | 预检失败 → 回到计划/澄清，不允许正式执行 |
| 7 正式执行 | 预检通过后点击“开始执行” | 潮位尺进入执行；事件条带实时；显示 run_mode=real | runner receipt、lease、artifact manifest | 设备/租约失败 → `INFRA_ERROR` 或 `BLOCKED_HUMAN`；dry_run 不能作为证据 |
| 8 自愈 | 执行异常 | 自愈记录：问题、根因、修复、验证；不隐藏失败 | 自愈事件与证据 | 修复失败 → 等待人工/停止；不得伪造通过 |
| 9 核验 | 执行结束 | 结论页签：机器结论、复算、分歧、根因 | verdict report；C4/C5 评估 | 分歧 → 阻断 PASS，`VERDICT_DIVERGENCE` |
| 10 归档 | 终态前 | 门禁页签 C1 至 C7 全部评估；归档进度 | archive receipt、playbook、failure candidates | 写回失败 → 终态不可写；`no_reusable_knowledge` 需理由 |
| 11 知识回写 | 归档后自动 | 知识页签：playbook、failure、script fix；状态 candidate | `playbook.created` 事件 | 候选不自动 approved；需人工治理 |
| 12 下一次复用 | 新任务受理 | 相似页签显示上一条 playbook 与复用块 | 检索包引用 | 差异/警告必须展示；应用块需重新审批 |

关键 UI 规则：

- “批准计划”与“开始执行”是两个不同按钮，不能合并。
- 预检通过不等于执行通过；预检结果用墨灰“预演”标签，不进入“今日通过”。
- `task.completed` 只在 C1 至 C7 与归档完成后出现；UI 不使用“完成”描述更早状态。
- 任何阶段失败都保留已产生的证据，不整页清空。

### 9.2 模型切换

```
入口 A：模型页 → 作用域（全局/Agent/任务）→ 选择对象 → 切换模型
入口 B：任务详情右栏 → 模型绑定 → 切换
入口 C：命令面板 → “切换全局模型”
```

步骤：

1. **选择作用域**：全局、Agent、任务。切换显示影响范围与优先级链。
2. **选择目标模型**：只列健康、能力满足、catalog 未过期的模型；显示家族、能力、健康、延迟。
3. **校验**：调用 `POST /models/test` 或等价校验；显示能力检查结果（json_schema/tool_calling/vision）、配额、provider 健康。
4. **选择生效方式**：
   - `下一轮生效`（默认）：当前 turn 不受影响；UI 显示“下一轮生效”。
   - `安全点中断`：显式选择，说明“当前轮会在安全点停止，然后应用新绑定”。
5. **确认**：显示旧 → 新、影响对象数量、binding revision、actor。
6. **结果**：
   - 成功：有效绑定更新，显示新 binding_id 与“下一轮生效/已生效”。
   - 409 revision 冲突：提示“配置已被他人修改”，刷新后重新选择，不覆盖。
   - 422 能力不满足：就地显示缺哪项能力，不静默降级。
   - `MODEL_BLOCKED`：氧化红“永久错误，需人工处理”，不自动切换。
7. **回滚**：审计列表提供“恢复上一绑定”，同样走校验与确认。

UI 约束：

- 不重启服务的说明必须出现在切换抽屉，而不是藏在文档。
- 来源 `compiled_fallback` 不可伪装成用户选择；徽章显示 `回退`。
- 切换后任务详情右栏保留旧绑定历史，直到新绑定实际使用。

### 9.3 接管

```
观察：任务详情 → 接管页签 → 获取观察（角色 2+）
交互：任务详情 → 接管页签 → 获取交互（角色 3 自己 / 4 任意）
```

步骤：

1. **检查前置**：任务非终态；存在 executor session；权限满足。
2. **选择模式**：观察（只读，不暂停）或交互（独占，暂停 agent）。
3. **获取租约**：
   - 成功：显示 lease_epoch、控制者、空闲倒计时。
   - 冲突 409：显示当前控制者与 epoch，提供“观察”或“稍后重试”，不提供强抢。
4. **安全暂停**：交互模式在下一个 turn boundary 暂停；若设备动作进行中，显示“等待当前设备动作完成”，不中途暂停。
5. **回放历史**：终端加载 backlog，显示分隔线“以上为历史回放”；用户可选择“跳到最新”。
6. **输入**：发送文本到同一 native session；显示“已注入，等待下一轮”；支持中断当前轮（确认）。
7. **释放**：
   - 手动释放：恢复 agent，保留 checkpoint；“已确认 effect 不会重放”。
   - 超时释放：默认 30 分钟空闲，最后 5 分钟赭石倒计时；自动释放后显示事件。
8. **断线重连**：从 cursor 恢复；显示“重连中”；输入禁用；任务不受影响。
9. **审计**：每次 acquire/pause/input/release/timeout 都有 actor、时间、结果；UI 显示“本次由谁控制”。

### 9.4 推送订阅

```
推送页 → 新建订阅 → 选择通道 → 配置过滤 → 测试发送 → 启用
```

步骤：

1. **选择通道**：terminal / file / webhook / sse。每类显示前置条件与限制。
2. **配置过滤**：事件类型、最低严重级别、项目/任务；显示“将命中哪些事件”的示例。
3. **通道配置**：
   - terminal：本机 CLI watch；说明需要本机订阅。
   - file：仅 `var/outbox/` 下路径；显示轮转策略。
   - webhook：HTTPS + allowlist；secret 只填 `cred://` 引用，不回显。
4. **测试发送**：发送 `push.test` 合成事件；明确“不是任务结果”；显示 delivery id 与结果。
5. **启用**：保存后显示“已启用”；投递时间线出现测试记录。
6. **失败处理**：
   - 重试：1s、5s、30s、5m、1h；UI 显示下一次重试。
   - 死信：显示最后错误与响应码；角色 4 可重试或丢弃。
7. **关闭**：kill switch 立即停止新投递；不删除历史。

### 9.5 知识治理

```
候选 → 佐证 → 批准 → （陈旧 / 撤回）
             ↘ 争议
```

| 动作 | 角色 | UI | 规则 |
|---|---|---|---|
| 创建候选 | 系统/3 至 4 | 知识详情/写回卡片 | 必须 provenance；模型生成标注 |
| 佐证 | 4 | 详情“佐证” | 需新证据或独立来源 |
| 批准 | 4 | 确认抽屉 + review receipt | 不可自动批准；显示适用范围 |
| 标记争议 | 3 至 4 | 反馈/争议 | 需理由；保留双方证据 |
| 标记陈旧 | 4 | 治理菜单 | 需新版本/pin/反例 |
| 撤回 | 4 | 危险确认 | 保留修订，不物理删除 |
| 合并 | 4 | 对比抽屉 | 生成新修订，旧条目指向新条目 |

UI 必须显示“批准不等于永久正确”；stale/disputed 在检索结果中显式标注。

### 9.6 SSE 实时与降级

1. 连接：`GET /api/aitest/v2/events/stream`，携带 `Last-Event-ID`。
2. 正常：命令栏苔绿点“实时”；事件按 seq 去重；DOM 不重复插入。
3. 断线：3s 内显示赭石“降级轮询 · 5s”；开始轮询 `GET /events?after=N`；页面顶部 1px 赭石线。
4. 恢复：从最后 seq 重连；去重；显示“已恢复实时”；不重复 toast。
5. 离线：氧化红点“离线”；写操作禁用；保留表单；恢复后提示“有 3 条更新”。
6. 页面隐藏：暂停脉冲与自动滚动；恢复可见时拉取增量。

### 9.7 停止 / 取消

- **停止执行中任务**：危险确认“停止后当前执行终止，证据保留，不产生产品结论”；终态 `STOPPED`，C7 仍要求。
- **取消未执行任务**：可跳过 C2/C3，但需要归档回执；不得声称结论。
- **停止接管**：只释放控制，不停止任务。
- **停止圆桌**：停止后续轮次，保留已产生内容。
- 所有停止操作显示影响对象与不可逆点；不使用“确定/取消”模糊文案。

### 9.8 相似块应用到计划

1. 在“相似”页签选择一条命中与可复用块（case-set/oracle/preflight）。
2. 点击“应用到计划” → 抽屉显示将新增/修改的用例、oracle、预检项。
3. 确认：创建新的计划草案修订，旧批准失效；审计记录来源引用与 actor。
4. 结果：跳到计划页签，显示“草案 rev 4（由 kb-1042 生成）”；必须重新评审与批准。
5. 失败：计划已冻结/无权限/引用失效 → 就地错误，不创建半成品修订。

### 9.9 功能开关与维护

- 关闭能力：确认框列出受影响页面与写操作，不删除数据；输入能力名确认。
- 维护模式：全局横幅 + 写操作禁用；只读页面保留；显示预计恢复时间。
- 开关未知值：视为关闭；UI 显示“未知值，已按关闭处理”，不提供“强制开启”。

| 预检 | 蓝“预检” | 否 | 查看 10/20 次、停止 | 把预检当完成证据 |
| 执行中 | 蓝“执行中” | 否 | 暂停、停止、接管、查看证据 | 编辑冻结计划 |
| 等待人工 | 朱砂“等待人工” | 否 | 接管、批准继续、停止 | 自动继续 |

| 归档 | 蓝“归档” | 否 | 查看写回、导出 | 新增长期执行 |

### 10.2 门禁文案

| 门禁 | 名称 | 通过条件（UI 摘要） | 失败文案 |
|---|---|---|---|
| C1 | 计划 | 已批准不可变修订 + assurance 通过 + 审批记录 | 计划未批准或保证门禁未通过 |
| C2 | 真实执行 | run_mode=real + 节点签名 receipt + lease + 端点身份 | 缺少真实执行回执，预演不能作为证据 |
| C3 | 产物完整 | manifest 哈希匹配，必需文件齐全 | 产物清单不匹配或文件缺失 |
| C4 | 独立结论 | 机器复算完成，runner 与复算无分歧 | 结论分歧未解决 |
| C5 | 证据充分 | 每个用例的必需证据齐全，无空捕获 | 缺少 3 个用例的串口日志 |
| C6 | 知识回写 | playbook + failure 已写入，或有明确不复用理由 | 尚未写回知识 |
| C7 | 可复现 | lock、lstest pin、模型绑定、环境指纹齐全 | 复现清单不完整 |

### 10.3 空状态文案

| 页面 | 标题 | 解释 | 主动作 |
|---|---|---|---|
| 总览（新部署） | 还没有任务 | 从一条需求开始，平台会先检索相似任务，再生成计划。 | 新建任务 |
| 任务列表 | 没有匹配的任务 | 当前筛选没有结果。清除筛选，或从一条需求开始。 | 清除筛选 / 新建任务 |
| 知识 | 没有找到匹配知识 | 试试放宽状态或项目筛选；也可以查看工具知识库。 | 放宽筛选 / 查看工具库 |
| 节点 | 还没有节点 | 注册第一台节点后，平台才能调度真实设备。 | 注册节点 |
| 模型 | 尚未同步模型目录 | 同步目录后才能创建绑定；不会重启服务。 | 同步目录 |
| 推送 | 还没有推送订阅 | 创建 CLI 订阅，任务完成时在终端收到通知。 | 创建 CLI 订阅 |
| 圆桌 | 还没有讨论 | 选择角色与模型，对计划做一次结构化评审。 | 发起讨论 |
| 接管 | 尚未启动执行会话 | 任务进入执行后才能接管。 | 返回任务 |

### 10.4 错误文案公式

```
[发生了什么] + [影响范围] + [下一步] + [请求 ID / 事件 ID]
```

示例：

- “任务投影加载失败。当前显示 30 秒前的缓存，结论可能不是最新。重试，或复制请求 ID `req-8f2a` 给管理员。”
- “Webhook 被 allowlist 拒绝。该订阅不会收到事件，任务本身不受影响。请角色 4 检查目标地址。”
- “接管租约冲突。当前控制者是李工（epoch 7），你的请求未生效。可以观察，或稍后重试。”

禁止：

- “出错了”“未知错误”“请稍后再试”单独出现。
- 把服务端堆栈、SQL、文件路径暴露给普通用户。
- 用 toast 承载需要用户采取行动的错误；错误必须留在页面内。

### 10.5 数据格式

| 类型 | 格式 | 示例 |
|---|---|---|
| 任务 ID | `ait-YYYYMMDD-NNNN` | `ait-20261026-0412` |
| 事件 ID | `evt-` + 短 UUID | `evt-7f3a9c2e` |
| 绑定 ID | `mb-` + 短 ID | `mb-2c91a0` |
| 租约 ID | `lease-` + 短 ID | `lease-9f2` |
| 哈希 | 默认 12 位，复制完整 64 位 | `9f2a1c8e4b70` |
| 时间 | 本地时区 + 相对时间 | `14:18:32 CST · 2 分钟前` |
| 时长 | `1h 24m` / `42s` | 不使用 `01:24:00` 除非终端 |
| 百分比 | 0 至 100，整数；阶段专用 | `62%` |
| 文件大小 | `86 MB`，1 位小数 | `1.4 GB` |
| 版本 | 原文，不截断语义 | `5.1.44 → 5.1.48` |

规则：

- 数字使用 `tabular-nums`；表格右对齐。
- 哈希与 ID 不换行；详情完整值允许 `overflow-wrap: anywhere`。
- 相对时间只在 24h 内使用；超过显示日期。
- 所有时间显示时区缩写，避免跨节点误读。

### 10.6 禁止的声明

- “已完成”用于任何未通过 C1 至 C7 与归档的任务。
- “验证通过”用于 dry_run、mock、replay、recorded。
- “AI 已确认”替代证据。
- “100% 准确”“零误判”“永不失败”。
- “自动修复成功”而没有修复后的验证证据。
- “多模型评审”而实际 `PANEL_DEGRADED` 或单一家族。
- 原型中的 mock 数据被描述为真实运行结果。

## 11. 可访问性

目标：WCAG 2.2 AA；键盘完整可用；屏幕阅读器可理解；不依赖颜色。

### 11.1 对比度

| 组合 | 比率 | 结论 |
|---|---|---|
| `#1B2A2E` on `#F4F0E6` | 13.0:1 | AAA |
| `#43585B` on `#F4F0E6` | 6.6:1 | AA |
| `#5E7072` on `#FCFAF4` | 5.0:1 | AA |
| `#1F5F5B` on `#F4F0E6` | 6.5:1 | AA |

### 11.2 键盘

| 全局 | `Tab` / `Shift+Tab` | 按 DOM 顺序移动；跳过隐藏元素 |
| 全局 | `Ctrl/Cmd + K` | 打开命令面板 |
| 全局 | `Esc` | 关闭最上层弹层/抽屉；焦点回到触发元素 |
| 命令甲板导航 | `Tab` / 方向键 | 在编号导航项间移动；Enter 进入 |
| 页签 | 左/右方向键 | 切换 tab；Home/End 首尾 |
| 表格 | 上下方向键 | 行焦点移动（若实现 roving tabindex） |
| 门禁印列 | 左/右方向键 | 印章间移动；Enter 打开详情 |
| 抽屉/弹窗 | `Tab` 循环 | 焦点陷阱；关闭后归还 |
| 终端 | `Tab` 离开 | 提供“离开终端”按钮，不困住键盘 |
| 接管输入 | `Ctrl/Cmd + Enter` | 发送；`Esc` 取消聚焦 |

- 所有图标按钮有 `aria-label`。
- 所有操作可通过键盘完成；拖拽不是唯一方式。
- 跳过链接“跳到主内容”作为第一个可聚焦元素。
- 焦点顺序与视觉顺序一致；不使用正 tabindex。

### 11.3 语义结构

- 页面：`header`、`nav`、`main`、`aside`、`footer`；`main` 有 `aria-labelledby` 指向页面标题。
- 页签：`role=tablist/tab/tabpanel`，`aria-selected`、`aria-controls`。
- 表格：`caption`、`th scope`、`aria-sort`；空表有说明。
- 状态徽章：文本可读，不只用背景色；`aria-label` 包含完整状态。
- 门禁印列：`role=list`；每项 `aria-label="C1 计划 已通过"`。
- 进度条：`role=progressbar` + `aria-valuenow/min/max` + 文本阶段名；不确定进度用 `aria-busy`。
- 实时区域：事件/队列更新使用 `aria-live="polite"`，批量更新合并；错误用 `role="alert"`。
- 图标装饰 `aria-hidden="true"`；有语义的图标配文字。

### 11.4 屏幕阅读器

- 任务详情页签切换后，焦点移到 tabpanel 标题或面板容器（`tabindex=-1`），并播报“证据，14 个文件”。
- 终端提供“文本日志”视图，按行可读；不使用 canvas 作为唯一内容。
- 图表/门禁印列提供表格替代（隐藏但可读，或“查看数据表”按钮）。
- 复制按钮播报“已复制任务 ID”。
- 倒计时（接管空闲）使用 `aria-live="off"`，只在 5 分钟与 1 分钟播报，避免每秒打断。

### 11.5 颜色与形状

- 通过：海玻璃绿 + 勾形；失败：氧化红 + 叉形；阻塞：朱砂 + 暂停；待定：空心墨线方块；不适用：斜线填充。
- 陈旧：灰 + 虚线边框 + “陈旧”文字；不只用低饱和。
- 争议：赭石 + “有争议”文字；与失败红区分。
- 图表系列使用不同形状/线型，不只颜色。

### 11.6 动效与前庭安全

- `prefers-reduced-motion: reduce` 时：移除位移、脉冲、扫光、自动滚动；保留颜色与数值变化。
- 不使用视差、缩放抖动、快速闪动。
- 运行中扫光频率不超过 2.2s；若用户开启减少动态，静止。
- 没有任何自动播放的音频/视频。

### 11.7 缩放与触控

- 200% 缩放不出现横向滚动（表格容器除外）；文本不截断关键结论。
- 触控目标最小 44 × 44px；表格行内按钮不密集堆叠。
- 手机横屏接管：终端可用；输入区不遮挡。
- 双击缩放不禁用。

### 11.8 表单

- 每个输入有可见 label；不用 placeholder 代替 label。
- 错误与字段关联 `aria-describedby`；错误文本具体。
- 必填标记 `aria-required`；不只靠星号。
- 保存失败保留输入；不重置表单。
- 危险确认要求输入或勾选，不用默认勾选。

### 11.9 可访问性验收

- 键盘走查：仅用键盘完成“新建任务 → 批准 → 查看证据 → 接管观察”。
- 屏幕阅读器走查：NVDA + Edge/Chrome，检查页签、表格、门禁印列、终端文本视图。
- 对比度：所有文本组合用工具核对；状态徽章文字 ≥ 4.5:1。
- 200% 缩放：1440 与 1024 宽度下无内容丢失。
- 减少动态：系统设置开启后，无位移动画。
- 自动化：接入 axe-core（本地依赖）作为辅助，不替代人工。

## 13. 动效

### 13.1 原则

- 动效只表达状态变化、空间关系或因果，不做装饰。
- 每个动画必须有 `prefers-reduced-motion` 路径。
- 只使用 `transform`、`opacity`、`background-color`、`border-color`；不触发布局。
- 不制作“AI 思考”无限旋转；用明确的阶段文字与已用时间。

### 13.2 允许的动效

| 场景 | 动效 | 时长 | 减少动态 |
|---|---|---|---|
| 页面进入 | 内容组 opacity + 3px 上移 | 180ms | 直接显示 |
| 抽屉 | translateX 14px + opacity | 260ms | 直接显示 |
| 弹窗 | opacity + scale 0.985 → 1 | 180ms | 直接显示 |
| 导航/页签状态标记 | opacity + scale 0.9 → 1 | 180ms | 立即出现 |
| 行 hover | 背景/边框 | 120ms | 保留颜色变化 |
| 事件追加 | 新行 1px 高亮淡出 | 600ms | 直接插入 |
| 运行中阶段 | 2.2s 扫光 | 循环 | 静止 |
| 实时连接 | 2.8s 脉冲点 | 循环 | 静止 + 文字 |
| 按钮按下 | scale 0.985 + 内阴影 | 70ms | 仅颜色变化 |
| Toast | translateY 6px + opacity | 180ms | 直接显示 |
| 门禁状态变化 | 颜色 + 形状切换 | 180ms | 立即切换 |

### 13.3 禁止的动效

- 全屏彩带、粒子、庆祝爆炸。
- 自动轮播的指标卡。
- 长时间骨架闪烁。
- 数字滚动计数（会延迟阅读）。
- 让列表行随机重排的“实时动画”。
- 鼠标跟随光斑/倾斜卡片（档案工具不需要）。
- 用动画掩盖加载失败。

## 14. 安全与隐私（UI 层）

1. **永不显示密钥**：provider key、webhook secret、SSH 私钥、cookie、authorization 均不进入 DOM。只显示 `credential_ref` 是否存在。
2. **脱敏**：事件 payload、终端输出、知识片段、日志下载均经过服务端脱敏；前端渲染 `[redacted]`。
3. **权限**：写按钮在 UI 禁用并在服务端再次校验；角色 4 的全局操作有审计。
4. **危险操作**：停止、释放租约、撤回知识、关闭 V2、删除订阅、重建索引均需二次确认，确认文案列出不可逆后果。
5. **下载**：证据/交付/审计下载记录 actor、task、file、时间；不暴露文件系统绝对路径。
6. **Webhook**：只接受 HTTPS 与 allowlist；UI 不回显 secret；测试发送使用合成事件。
7. **知识导入**：扫描 secrets/PII；发现的文件拒绝或要求人工确认；不把原文写入 UI 缓存。
8. **接管**：不提供 raw shell；终端只连接已注册会话；输入经过权限与重复 effect 校验。
9. **XSS**：所有用户内容默认转义；Markdown 渲染使用白名单；不执行内联脚本；CSP 禁止外部资源。
10. **CSRF**：所有写请求携带 CSRF token；UI 客户端统一处理 401/403。
11. **无外部资源**：不引用 CDN、外部字体、外部图片；xterm 本地打包。
12. **审计可见**：接管、模型切换、知识提升、推送配置、功能开关都有审计行与 actor。

## 16. 已知缺口与开放问题

### 16.1 设计交付的边界

1. **原型是静态 mock**：所有数据、状态、进度、终端输出均为示例，不代表后端已实现。原型不发送任何网络请求。
2. **未接入真实 API**：页面字段依据契约与计划推导；API 冻结后需逐页核对字段名、枚举与错误码。
3. **字体未打包**：使用系统字体栈，Windows 内网可用；展示体回退 Palatino/宋体，正文回退 Segoe UI/雅黑，等宽回退 Consolas。未引入外部字体。
4. **图标未最终定稿**：原型使用简化内联 SVG；实现阶段需统一为本地图标集，保持 1.5px 风格。
5. **xterm 未打包**：原型用 CSS/HTML 模拟终端外观；实现阶段需本地打包 xterm（P7-07），不得使用 CDN。
6. **浅色为唯一全局主题**：终端与接管局部使用深色 `#12211F`，不是全局深色主题；未设计全局深色模式。若未来需要，必须新增 token 并重新验证对比度。
7. **移动端接管能力有限**：手机可查看与输入，但长时间终端操作建议桌面；这是使用建议，不是功能缺失。
8. **C8 测试有效性门禁未定义**：P4-12 为占位；UI 预留“测试有效性”位置，但不显示未定义的通过状态。
9. **高对比度模式未单独设计**：依赖系统强制颜色与语义结构；需要在实现阶段用 Windows 高对比度模式验证。
10. **真实设备截图未纳入**：设计阶段不伪造设备截图；节点/设备页使用结构化数据与状态，不使用假照片。

## 18. 文件清单与评审方式

| 文件 | 用途 | 状态 |
|---|---|---|
| `docs/v2/UI-DESIGN.md` | 本规范 | 设计交付 |
| `design/design-tokens.json` | 令牌源 | 可解析 |
| `assets/brand/ark-logo.svg` | 品牌图形标 | 可独立打开 |
| `design/wireframes/README.md` | 线框索引与阅读顺序 | 设计交付 |
| `docs/v2/wireframes/README.md` | P7-00 计划路径到 `design/wireframes/` 的指针 | 设计交付 |
| `design/wireframes/01-overview.md` 至 `15-system.md` | 15 个页面线框 | 设计交付 |
| `design/ui-prototype.html` | 可点击原型（mock） | 本地打开 |
| `docs/v2/UI-REVIEW.md` | 评审清单、验证结果、缺口 | 设计交付 |
| `docs/v2/UI-ORIGINALITY.md` | 不复用声明、原创性清单、grep 证据 | 设计交付 |

评审顺序建议：

1. 先看 `design/ui-prototype.html` 的总览、任务详情、模型、接管四页，确认视觉方向与信息密度。
2. 再看 `UI-DESIGN.md` 第 6、8、9 节，确认 IA、页面状态与流程。
3. 最后看线框与 `UI-REVIEW.md`，确认边界与缺口。
4. 评审通过后，P7-01 才进入实现；实现不得绕过本规范新增未登记的 token 或页面状态。

原型打开方式：

```
直接双击 design/ui-prototype.html
或
python -m http.server 8080 --directory design
然后访问 http://localhost:8080/ui-prototype.html
```

原型不需要网络；若浏览器阻止本地脚本，使用本地 HTTP 服务即可。原型中的所有交互只改变前端 mock 状态，刷新即重置。

**设计结论**：NoahsArk 控制台不是“更多卡片”，而是“更少误判”。门禁、证据、模型来源与人类决断必须在同一视线内；任何漂亮但不能解释的界面都不通过本规范。
