## 1. 设计定位与理由

### 1.1 为什么做 v3

v2「Voyage Ledger / 航次档案」已覆盖 15 个页面、11 个主导航、任务详情 11 个页签和完整 mock 数据，但用户反馈“功能覆盖可接受，UI 缺少设计感”。问题不在功能，而在视觉层级：

- 页面标题、卡片标题、表格文字的字号差距偏小，阅读路径平；
- 双行顶栏、编号导航、印章式徽标同时发声，视觉噪音多；
- 纸面纹理、暖色底、多套语义色让界面更像档案系统，而不像精密仪器；
- 卡片、按钮、表格的圆角与间距偏碎，缺少统一节奏。

v3 不重写信息架构，也不减少事实。它把 v2 的“档案感”换成“安静仪器感”：**让事实更清楚，让装饰更少，让操作路径更确定。**

### 1.2 Quiet Instrument 的定义

Quiet Instrument 不是“Apple 主题皮肤”。它是一套面向测试运营的控制台设计语言：

- **安静**：大面积白色与柔灰，只有一个蓝色强调色；状态色只在状态上出现。
- **仪器**：数字、门禁、证据、租约、模型绑定仍是第一等公民；每个数字都能回到来源。
- **克制**：不使用彩虹渐变、玻璃拟态堆叠、装饰性彩色边条或营销式大图。
- **可读**：编辑级标题建立阅读顺序，表格和终端保持高频操作所需的密度。
- **可预期**：同一类事实在 15 个页面使用同一种组件与同一种颜色含义。

### 1.3 与 v2 的关系

- 保留 v2 的全部路由、mock 数据、交互脚本、页面事实和 11 个主导航。
- 只替换视觉层与外壳结构；`design/apple/ui-prototype.html` 是独立副本。
- v2 文件未被修改，可以直接并排打开比较。
- 如果用户不采纳 v3，删除 `design/apple/` 与本文档即可回滚，不影响 v2。

## 2. 借鉴的 Apple 原则

### 2.1 采纳

| 原则 | 在 NoahsArk 中的落地 |
| --- | --- |
| Clarity（清晰） | 页面标题 56/40/32px 三级缩放；每个页面只保留一个主标题；按钮使用结果动词；表格首列是任务或对象名。 |
| Deference（内容优先） | 顶栏、导航、卡片全部后退为白/灰表面；不使用背景大图、装饰插画或品牌墙。内容本身就是视觉主体。 |
| Depth（克制的层次） | 默认卡片无阴影，仅靠白面、柔灰底与 1px 发丝线分层；只有分段控件选中态、弹层、Toast 和滚动后的顶栏使用阴影。 |
| Typographic hierarchy | 系统字体、紧字距标题、16px 卡片标题、14px 正文、12.5px 说明、11px 眉题；最多两种字族（系统无衬线 + 等宽）。 |
| Generous whitespace | 8pt 间距体系；桌面主区 48px 上留白、40px 侧边距；卡片 26px 内边距；页面最大宽度 1160px。 |
| One accent | 唯一强调蓝 `#0071E3` 只用于主按钮、焦点、进度和少量信息态；链接使用更深的 `#0066CC` 保证对比。 |
| Material, not decoration | 顶栏使用半透明白 + `saturate(180%) blur(20px)`；材质只服务于“始终可见的导航”，不铺满整页。 |
| Direct labeling | 不使用只有图标的危险操作；图标按钮必须有 `aria-label`；状态徽标始终带文字。 |
| Progressive disclosure | 任务详情用 11 个分段页签承载计划、用例、执行、证据、结论、门禁、知识、相似、接管、日志；首屏只给结论与阻断点。 |
| Reduced motion | 页面进入 320ms 淡入上移；交互 140–220ms；`prefers-reduced-motion` 下全部降为 0.001ms，并停止实时圆点脉冲。 |

### 2.2 明确拒绝

| 被拒绝的做法 | 原因 |
| --- | --- |
| 把控制台做成 Apple 产品营销页 | 测试运营需要表格、门禁、证据和终端，不是大图 + CTA。 |
| 全屏产品摄影、3D 产品渲染、滚动叙事的巨幅 hero | 与任务无关，且会增加资源与可访问性负担。 |
| 玻璃拟态铺满所有卡片 | 会让高密度文字失去对比；只保留顶栏一处材质。 |
| 彩虹渐变、彩色边条、彩色描边卡片 | 颜色会与状态语义冲突，也会掩盖真正的阻断。 |
| 加载 SF Pro 字体文件 | 授权与离线约束不允许；改用本地系统字体栈。 |
| 复制 Apple 的全局导航结构 | NoahsArk 的 11 个一级入口是业务结构，不套用 Apple 的产品线导航。 |
| 用动画制造“高级感” | 动效只解释状态变化；没有信息目的的循环动画一律不加。 |
| 把“预检通过”做成绿色大成功页 | 预检不是完成证据；视觉上也不允许夸大。 |

## 3. 明确不从 Apple 复制的内容

本变体**没有**使用或模仿以下 Apple 资产：

- 没有 Apple 标志、Apple 字样、产品名称、产品照片、包装图、零售店图或任何商标素材。
- 没有 SF Pro / SF Mono 字体文件；只使用本机系统字体回退栈。
- 没有 Apple.com 的文案、版式比例、导航条目、产品卡片结构或营销话术。
- 没有 iOS/macOS 系统控件截图或素材；开关、分段控件、胶囊按钮均为本项目 CSS 实现。
- 没有 Apple 的“California”署名、隐私文案、价格表或“Designed by Apple”类表述。
- 没有声称与 Apple 存在合作、授权或隶属关系。

“Apple-inspired”在本项目中仅指：**清晰、留白、单一强调色、系统字体、克制的材质与动效**这些通用设计原则。

## 4. 设计令牌

令牌文件：`noahsark/design/apple/design-tokens.json`，CSS 前缀 **`--naa`**。

> 兼容说明：原型保留了 v2 JS 内联样式使用的 `--na-*` 只读别名，它们全部指向对应的 `--naa-*` 令牌；本次新增样式只使用 `--naa-*`。这样既能保留原有行为，也不会让两套颜色值分叉。

### 4.1 颜色

| 语义 | 值 | 用途 |
| --- | --- | --- |
| canvas | `#F5F5F7` | 页面柔灰底 |
| raised | `#FFFFFF` | 卡片、表格、任务头、页签轨道 |
| subtle | `#FBFBFD` | mock 状态条、轻量分区 |
| sunken | `#EDEDF0` | 轨道、开关关闭态 |
| ink primary | `#1D1D1F` | 标题、正文、导航选中胶囊 |
| ink secondary | `#424245` | 表格正文、次级文本 |
| ink tertiary | `#5F5F64` | 说明文字 |
| ink quaternary | `#6E6E73` | 时间、ID 等元数据；仍保持 ≥4.5:1 |
| accent | `#0071E3` | 主按钮、焦点、进度 |
| accent ink | `#0066CC` | 链接与可点击文本 |
| ok | `#1A7F45` | PASS、已验签、已归档 |
| warn | `#9A6400` | 等待人工、漂移、BLOCKED |
| danger | `#C4312A` | FAIL、错误、危险操作 |
| neutral | `#6E6E73` | 未执行、离线、未知 |
| disputed | `#8A5A00` | 知识争议（与 WARN 区分） |
| terminal | `#1D1D1F` | 终端与深色操作面 |

状态色规则：

1. 颜色永远不是唯一信息：徽标始终带文字，门禁方块带 ✓ / ✗ / ! 或数字。
2. 同一颜色只表达一类含义：蓝色只表示“可交互/进行中”，绿色只表示“已通过/已验签”，琥珀只表示“等待/漂移/阻断”，红色只表示“失败/危险”。
3. 卡片、行、导航不使用彩色侧边条；选中态使用整块浅灰或深色胶囊。

### 4.2 字体

```css
-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text",
"Segoe UI", "Microsoft YaHei UI", sans-serif
```

- 不加载任何外部字体；Windows 通常落到 Segoe UI / Microsoft YaHei UI，macOS 落到 SF Pro。
- 等宽：`SFMono-Regular, Cascadia Mono, Cascadia Code, Consolas, Microsoft YaHei UI, monospace`，用于 ID、哈希、时间、终端。
- 标题字距 `-0.035em`；正文 `-0.006em`；眉题 `+0.07em`。
- 字号：桌面标题 56px；平板 40px；手机 32px；总览陈述句 46/32px；任务详情标题 38/26px；卡片标题 16px；正文 14px；说明 12.5px。
- 行高：标题 1.04–1.15；正文 1.55；表格 1.4；终端 1.75。

### 4.3 间距、圆角、阴影、动效

- 间距：8pt 基准，允许 4px 半档；卡片 26px，紧凑卡片 20px，移动端 20/16px。
- 圆角：10 / 14 / 18 / 22 / 28 / 999px；任务头与总览使用 28px，普通卡片 22px，移动端 18px。
- 阴影：默认 `none`；分段控件选中 `0 1px 3px rgba(0,0,0,.09)`；滚动后的顶栏 `0 10px 30px rgba(0,0,0,.06)`；弹层 `0 30px 90px rgba(0,0,0,.24)`。
- 动效：140ms（hover/按压）、220ms（页签、开关）、320ms（页面进入）；统一 `cubic-bezier(.25,.1,.25,1)`。
- 禁止：弹跳、循环漂浮、视差、滚动劫持、无意义的背景动画。

## 5. 布局与响应式

### 5.1 外壳高度

| 区域 | 桌面 | 平板 | 手机 |
| --- | --- | --- | --- |
| Mock 声明条 | 30px | 30px | 30px |
| 运行状态条（ribbon） | 28px | 28px | 26px |
| 顶栏（品牌、搜索、账户、新建） | 62px | 62px | 56px |
| 主导航行 | 48px（≥1024） | 0（抽屉） | 0（底部 Tab） |
| 主滚动区 | 剩余高度 | 剩余高度 | 剩余高度 |
| 底部 Tab | 无 | 无 | 64px + 安全区 |

主滚动区是唯一的滚动所有者；顶栏、状态条和底部 Tab 不随内容滚动。内容区最大宽度 1160px，桌面左右 40px，平板 28px，手机 20px。

### 5.2 断点

- **≥1200px**：11 个一级入口横向展开；双列详情 + 右侧上下文栏；4 列指标。
- **1024–1199px**：11 个入口仍横向展开，使用更紧的 32px 侧边距与 12.5px 导航字号；双列详情保留。
- **768–1023px**：主导航收入抽屉（菜单按钮）；单列详情；上下文栏移到内容下方；指标 2–3 列。
- **≤767px**：品牌精简、搜索变 44px 图标、账户隐藏；底部 5 个 Tab（总览/任务/思考/知识/更多）；任务表变成卡片；所有按钮至少 44px 高。

### 5.3 版式规则

- 每页只有一个 `h1`；眉题使用英文域标签 + 日期/状态，不承担标题职责。
- 页面标题不换行超过 2 行；手机端任务标题允许 2 行，并让操作按钮换行到下一行，避免挤压标题。
- 说明文字最大 64–66 个字符宽；正文段落不超过 75 个字符。
- 表格在窄屏不压缩列：外层容器内部横向滚动；只有任务列表在手机上改为卡片。
- 中文标题使用 `overflow-wrap:anywhere` 兜底，避免长 ID 或英文模型名撑破布局。

## 6. 外壳与导航

### 6.1 Mock 声明条

- 顶部 30px 白底条，明确写着 `DESIGN PROTOTYPE · MOCK DATA`、无后端、无真实执行、不调用模型、刷新重置。
- 这是产品诚实性的一部分，不是调试残留；任何截图都必须保留。
- 手机端仍保留，不隐藏。

### 6.2 运行状态条（ribbon）

- 28px 浅灰条，左侧 `NOAHSARK · QUIET INSTRUMENT · V3 PREVIEW`，中间 `prod · build 241026 · 最后事件`，右侧实时状态、角色、用户。
- 只承担环境与连接事实，不与主导航争夺注意力。
- 手机端只保留左侧标识，隐藏中间与右侧。

### 6.3 顶栏

- 左：内联 SVG 方舟标记（复用 v2 的原创图形，颜色改为墨黑 + 单点蓝）+ `NoahsArk` 字标 + `AI TEST OPERATIONS` 小字。
- 中：胶囊搜索框（`Ctrl K` 提示），点击打开命令面板。
- 右：实时/降级/离线胶囊、账户（桌面）、新建任务主按钮。
- 桌面主按钮蓝色胶囊；手机缩为 44px 圆形加号，并保留 `aria-label="新建任务"`。

### 6.4 主导航

- 11 个入口全部保留：总览、任务、思考、知识、节点与设备、模型、工具链与版本、推送、Agent、圆桌、系统。
- 桌面横向排列，居中；当前项为**深墨胶囊 + 白字**，不使用彩色下划线或侧边条。
- 任务入口保留待处理数量徽标。
- 导航行可横向滚动但不显示滚动条；1440px 下实测 11 项全部可见，无滚动。
- 平板（768–1023）和手机：主导航改为全屏抽屉，抽屉顶部有“导航”标题和 44px 关闭按钮；11 项以 52px 行高排列，带 `aria-current`。
- 手机底部 Tab 只有 5 项，第 5 项“更多”打开同一抽屉，保证 11 个入口都可到达。

### 6.5 接管模式

- 进入接管页时隐藏 ribbon、主导航和底部 Tab，主滚动区占满窗口。
- 页面顶部保留“返回任务”链接；终端与侧栏成为唯一主体。
- 这不是独立窗口，也不宣称真实接管；只是全屏专注布局。

## 7. 组件规格

### 7.1 按钮

| 类型 | 高度 | 圆角 | 颜色 | 用途 |
| --- | --- | --- | --- | --- |
| Primary | 42px（手机 44px） | 999px | 蓝底白字 | 每页唯一主操作：新建任务、提交审批、开始讨论、切换全局、进入接管 |
| Secondary | 42px | 999px | 白底墨字 + 发丝边 | 刷新、导出、取消 |
| Human decision（原 amber 类） | 42px | 999px | 墨黑底白字 | 批准计划、人工动作；不使用琥珀填充 |
| Danger | 42px | 999px | 白底红字 + 红边 | 释放控制、关闭 V2 |
| Ghost | 42px | 999px | 透明底蓝字 | 次级链接式操作 |
| Small / XS | 36 / 30px | 999px | 同上 | 表格行内操作；手机统一 44px |

- 所有按钮有 hover、active、disabled、focus-visible 状态。
- focus-visible 为 3px 蓝色外环、2px 偏移。
- 主按钮不使用渐变；按压只缩放到 0.985，不弹跳。

### 7.2 卡片

- 白底、1px `rgba(0,0,0,.07)` 发丝边、22px 圆角、26px 内边距。
- 默认无阴影；不使用左侧彩条、顶部彩线或彩色描边。
- 仅可点击的列表卡（知识结果、节点卡）在 hover 时换为 `#FBFBFD` 和略深边线。
- 卡片标题 16px/600；副标题 12.5px 灰色；卡片头与内容间距 18px。

### 7.3 徽标与状态

- 胶囊徽标，高 23px，11px/500；小号 20px。
- 每个徽标带文字；`dot` 只是辅助。
- 状态含义固定：绿=通过/验签，琥珀=等待/漂移/阻断，红=失败/危险，蓝=进行中/信息，灰=未执行/离线。
- 陈旧状态使用中性色 + 虚线边，不新增色相。
- 门禁：7 个圆角瓦片，每个包含状态圆点（✓/✗/!/数字）、`C1`–`C7` 和门禁名；通过/失败/阻断同时改变圆点与文字色，不只改变颜色。

### 7.4 页签

- 任务详情的 11 个页签使用 Apple 式分段控件：浅灰轨道、白色选中胶囊、1px 阴影。
- 页签栏在滚动时吸顶；支持左右方向键切换。
- 每个页签保留文字标签，证据与日志带数量。
- 移动端页签 44px 高、可横向滚动。

### 7.5 表格

- 表头 11px/600 灰色，无底色，只有发丝下边线。
- 行高由 14px 内边距形成；无斑马纹；hover 为 `#FBFBFD`。
- 首列左内边距 20px；数字列右对齐；操作列右对齐。
- 任务列表在手机变为卡片：标题、项目/设备、阶段、门禁、结论、证据、模型、更新时间逐项带标签，操作按钮固定在右上。
- 其他表格在窄屏保持表格语义，由外层容器横向滚动；不压缩中文列。

### 7.6 表单与输入

- 输入框高 44px、12px 圆角、1px 边线；focus 时蓝色边线 + 4px 浅蓝外环。
- 每个字段有可见 `<label>`；placeholder 只给格式示例。
- 下拉框使用 12×8 的自绘箭头（内联 data URI，不产生外部请求）。
- 单选与复选使用系统 `accent-color` 蓝色。

### 7.7 开关

- 视觉轨道 44×26px，真实点击区域 44×44px。
- 关闭为灰色轨道，开启为绿色；白色滑块位移 18px。
- 开关只用于可逆设置；危险操作仍走二次确认弹层。
- 有 `role="switch"` 与 `aria-pressed`。

### 7.8 终端

- `#1D1D1F` 背景、18px 圆角、12px 等宽、1.75 行高。
- 时间列灰色，角色列蓝色，成功绿色，警告琥珀，错误红色；颜色均配文字。
- 终端可聚焦，有 `aria-label`；接管页提供“复制可见文本”和“下载脱敏日志”按钮。
- 不使用扫描线、闪烁光标或循环动画。

### 7.9 弹层、抽屉、Toast、命令面板

- 遮罩：`rgba(0,0,0,.30)` + 6px 背景模糊。

## 9. 动效

- 页面进入：透明度 0→1、上移 8px→0，320ms。
- 页签切换：内容 220ms 淡入；分段控件选中胶囊即时切换背景与阴影。
- 按钮 hover：背景/边框 140ms；按压 `scale(.985)`。
- 卡片 hover：仅可点击卡片改变底色与边线，不做位移或放大。
- 开关：轨道 220ms、滑块 220ms。
- 实时圆点：2.6s 呼吸；仅表示连接状态。
- `prefers-reduced-motion: reduce`：所有动画/过渡降为 0.001ms，页面进入取消，实时圆点停止脉冲。
- 不使用：弹跳、循环漂浮、视差、滚动劫持、自动轮播。

## 10. 可访问性

### 10.1 已落地

- **焦点**：全局 `:focus-visible` 3px 蓝色外环；按钮、链接、输入、页签、门禁瓦片、开关均可键盘到达。
- **键盘**：Tab 顺序等于阅读顺序；Esc 关闭弹层/命令面板/抽屉；Ctrl/Cmd+K 打开命令面板；任务页签支持左右方向键；门禁瓦片支持 Enter。
- **触控目标**：手机端按钮、页签、chip、开关、链接至少 44×44px；导航抽屉项 52px；底部 Tab 64px。
- **语义**：`nav`、`main`、`header`、`table`、`role="dialog"`、`aria-modal`、`aria-current="page"`、`role="switch"`、`aria-pressed`、图标按钮 `aria-label`、表格 `scope="col"`。
- **状态不靠颜色**：所有状态徽标带文字；门禁带 ✓/✗/!；进度条带百分比；开关带滑块位置。
- **对比度**：用脚本对 15 个路由的文本节点逐项计算，正文/次级/三级文本在白色与 `#F5F5F7` 上均 ≥4.5:1；大字号 ≥3:1；脚本复测 0 项失败。终端文本在 `#1D1D1F` 上 ≥4.5:1。
- **减少动效**：完整支持 `prefers-reduced-motion`。
- **CJK**：使用系统中文回退字体；标题、元数据、表格设置 `overflow-wrap`；手机端表格卡片化，避免中文列被压成窄条；页签与按钮不裁切降部。
- **跳过链接**：保留“跳到主内容”。
- **弹层**：打开时焦点进入第一个可操作元素；关闭时焦点回到触发元素；抽屉有明确关闭按钮。

### 10.2 未完成 / 不声明

- **没有做 WCAG AA 认证**，也没有第三方审计；以上只是设计自查与脚本检查。
- 没有实现完整的焦点陷阱（focus trap）；这是静态原型的已知限制。
- 没有测试真实屏幕阅读器（NVDA/VoiceOver）组合；仅验证了 ARIA 结构与键盘路径。
- 颜色对比计算基于浏览器计算样式与最近的不透明背景；渐变/半透明材质下的极端组合仍需人工复核。
- 未提供深色模式；`color-scheme` 固定为 light。

## 13. 已知限制

1. **仅浅色模式**：Apple.com 的浅色语言是本次目标；深色模式需要单独设计状态色对比，未纳入本变体。
2. **系统字体差异**：macOS 会使用 SF Pro，Windows 使用 Segoe UI / Microsoft YaHei UI；字宽与行高会有 1–3% 差异。截图在 Windows Chrome 上生成。
3. **未做真实性能审计**：单文件、无外部资源，但未跑 Lighthouse；不应宣称性能分数。
4. **未做 WCAG AA 认证**：对比度与键盘路径已自查，仍需真实审计与屏幕阅读器测试。
5. **抽屉是整屏面板**：移动端没有“半屏 sheet”形态；这是为了让 11 个入口一屏可扫。
6. **长页面**：手机端总览与任务详情内容较长；这是保留全部运营事实的代价，已用卡片化与分段页签降低认知负担。
7. **工作台数据固定**：任务 0420 的新建、批准、切换模型等交互只改内存；刷新后回到初始 mock。
8. **未接入真实后端**：所有“真实执行”“接管”“模型切换”均为演示文案，不代表系统能力。

## 16. 设计自查口径

- 视觉层级：每页一个 56/40/32px 标题；卡片标题 16px；正文 14px；元数据 12.5px。

- 颜色：状态色只出现在徽标、门禁、进度与错误文案；没有装饰性彩色边条。
- 圆角：22px 卡片、999px 胶囊、18px 小卡；没有混用 2/3/4/6px 的旧圆角。
- 间距：8pt 体系；卡片 26px、页面 40px、移动端 20px。
