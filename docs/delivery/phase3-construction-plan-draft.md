## 1. 固定架构与不可协商边界

| # | 不变量 | 强制规则 | 执行位置 | 证据 |
|---|---|---|---|---|
| A1 | Linux 权威 | Linux 控制面是 Task、Revision、Approval、Gate、Run、Attempt、Lease、Device、Evidence、Verdict 的唯一权威写入方，也是最终判定唯一生成方。 | API、领域服务、数据库写权限 | 写权限矩阵测试；越权写入必须失败 |
| A2 | PostgreSQL 唯一正式数据库 | PostgreSQL 是唯一正式数据库。SQLite、ORM 私有文件、节点本地数据库都不得成为第二权威源。 | 数据层、迁移、备份 | 迁移清单；连接配置审计；备份恢复证据 |
| A3 | Windows 节点只报事实 | Windows Node Agent 只执行冻结工件并回传 `node_observed_*` 事实，`used_for_decision=false`。不得写 `business_verdict`、`verification_status` 或平台 PASS/FAIL。 | 节点协议、网关、数据库权限 | 节点令牌无权写判定表；契约测试 |
| A4 | 节点仅出站 | Windows 节点只发起出站长轮询，不开放入站管理端口，不使用 SSH、WinRM 或反向 shell 作为运行时控制通道。 | 节点服务、网络策略 | 端口扫描证据；出站连接测试 |
| A5 | 修订不可变 | 冻结后的 Revision、Execution Bundle、证据对象、已接受 manifest 不得原地修改。范围变化派生同任务新 Revision。 | 领域模型、存储层 | 不可变约束测试；更新请求必须被拒绝 |
| A6 | 审批与门禁 | 一个 Revision 只能有一个有效 Approval；G0 至 G7 按序推进；G1、G5、G6 不得跳过；`PASSED` 门禁不等于业务 PASS。 | 审批服务、门禁服务 | 唯一约束；门禁顺序测试；跳过请求失败 |
| A7 | 离线 spool | 节点事实先落本地 spool，再尝试上传；重连按幂等 replay，不重复执行已启动 Job；容量上限与保护策略必须显式。 | Node Agent、spool manager | spool 溢出测试；断网重放测试 |
| A8 | STOP-first | STOP 优先于排队工作；重连顺序固定为处理待送达 STOP、停止后续动作、补传、去重、核对 run/device/lease/epoch/occupancy、恢复领取。 | 网关、编排、节点 | STOP 优先级测试；六步时间线证据 |
| A9 | 五事分离 | 租约、占用、设备释放、证据完整性、最终判定是五个独立事实。释放只依赖 `local_stop_confirmed`、`safe_cleanup_done`、`occupancy_reconciled`；缺清理回执不等于证据不完整；PASS 可以与释放未确认并存。 | 领域服务、投影、UI | 分离矩阵测试；禁止等价文案扫描 |
| A10 | 五轴 fail-closed | 固定五轴：`execution_status`、`validity_status`、`business_verdict`、`evidence_status`、`verification_status`。只有 `COMPLETED / VALID / PASS / COMPLETE / PASS` 才能显示正式 PASS。未知、缺失、冲突、无法复算一律 `BLOCKED` 或 `NEEDS_REVIEW`，绝不降级为 PASS。 | 判定引擎、Linux 独立复核 | 轴组合测试；fail-closed 用例 |
| A11 | 内容寻址证据 | 证据载荷按 SHA-256 内容寻址；数据库只存索引、摘要、指针与访问级别；接收后不可覆盖；摘要不符进入 `NEEDS_REVIEW`。 | 证据服务、存储 | 摘要复算；覆盖请求失败；损坏检测 |
| A12 | 投影不是权威 | TaskCard、报告、知识、UI read model 都是可重建投影，不得反向写回 Task/Run/Verdict。UI 不自行推导状态，不把未知画成 0% 或 99%。 | 投影服务、前端 | 重建测试；禁止反向写测试 |
| A13 | TCL 后置 | TCL 适配、项目材料摄取、formal profile 生成属于后期适配层。平台核心、UI、架构、验收规则先完成。 | W8、Phase 6 | W8 入口门；TCL 边界检查 |

## 2. 阶段顺序与有序门

固定顺序：

`Phase 1 UI 设计/可运行高保真原型/Playwright 视觉 QA/冻结` -> `Phase 2 架构/数据/API/Node Agent/安全/部署/可观测性冻结` -> `Phase 3 施工方案评审/冻结` -> `Phase 4 验收方案评审/冻结` -> `Phase 5 实施波次 W0 至 W9` -> `TCL 适配与项目材料摄取` -> `Phase 6 T1-T6/L0-L5 验收` -> `F1-F4 最终验证`。

允许并行起草，不允许并行越门。Phase 2 可以在 Phase 1 冻结前起草，但 P2-09 冻结必须在 P1-08 冻结之后。Phase 4 可以在 Phase 3 评审期间起草，但 P4-08 冻结必须在 P3-07 冻结之后。Phase 5 的任何实现提交都必须在 P4-08 冻结之后。

3. 契约测试必须验证拒绝路径：未知 schema、未知枚举、越权、重复幂等键。
4. UI 视觉 QA 必须用真实浏览器，不接受静态截图替代。
5. 真机证据与模拟证据分目录、分 `mode`、分分母。
6. 独立评审者不得是同一波次的实现者。

### 10.3 profile、规则、脚本与参数生成

formal profile ID、规则、脚本和参数由平台或助手从受限外部项目材料与 lstest 知识生成，**不得向用户手工索要**。

生成链路：

1. 在授权窗口内读取受限外部材料，只在受控 staging 中处理。
2. 提取项目事实、串口与音频端点、唤醒词、用例意图与断言。
3. 归一化为平台内部 profile 候选，生成 `profile_id`、规则集、脚本、参数与 `content_digest`。
4. 用 lstest `preflight` 做静态校验，失败则回到候选修订。
5. 生成 Execution Bundle 候选，进入 G1 审批；审批只做批准/拒绝，不要求用户手写 profile。
6. 冻结后 runtime 不得再读 `E:\aswxStation\tmpskill\072101TCL`，只消费冻结包。

### 10.4 验收边界

1. W8 只证明适配器、生成式 profile、端点绑定和 T5 候选链路，不产生正式 PASS。
2. T5 必须使用独立 `run_id` 与 `mode=smoke`，不进入正式分母。
3. T6 使用冻结的生成式 profile、正式样本与 Linux 独立复核，才可产生正式判定。
4. 唤醒词通过判据是行为成功，不是固定时长；报告必须写清实际观察，不写推断阈值。
5. 设备释放、证据完整性、最终判定继续分离；TCL 适配不得把三者合并。
6. COM5/COM7 未使用必须作为负向检查：适配器启动后不得打开这两个端口。
7. 硬件复位不可用时不得判失败；普通 A 串口重启可用即可满足当前方案。

## 13. 受限 SSH 凭据使用政策（强制）

本节等同于总计划 §0.1，施工方案与验收方案在生成和冻结时必须完整包含。**本节是 P3-07 与 P4-08 冻结的前置条件；缺失则不得冻结，不得进入 Phase 5 或 Phase 6。**

- 写入禁令：口令、私钥、令牌、IP、用户名不得出现在任何方案、日志、报告、归档、提交或推送中。
- 使用范围：仅限授权的节点调试与验证；不得用于未授权主机、越权路径或与本计划无关的操作。
- 输出脱敏：执行命令的输出在记录或回传前必须脱敏，去除凭据、地址与身份信息。
- 访问登记：每次使用记录访问目的、时间、操作者和结果，写入对应阶段证据。
- 临时清理：使用后立即清理临时材料，不在工作区或证据目录残留凭据副本。
- 破坏性操作门禁：删除、重装、重置、格式化等破坏性操作必须先通过方案门，未获批准不得执行。
- 凭据处置：需要轮换或销毁时由操作方执行；代理不得读取、打印、复制或移动凭据文件。
- 适用范围：本政策覆盖 Phase 3、Phase 4、Phase 5、Phase 6 与最终验证的全部代理、脚本、日志、证据和报告。
- 违规处理：发现泄露立即停止相关工作，保留审计事实，清除泄露物，由操作方决定轮换；不得自行掩盖或继续同步。

## 14. 证据、完成标准与 STOP 条件

### 14.1 证据目录命名

统一模式：

`docs/delivery/evidence/phase3/<gate-id>/<wave-id>/<UTC-timestamp>-<short-ref>/`

每个目录至少包含：

| 文件 | 内容 |
|---|---|
| `manifest.json` | gate、wave、item_id、命令、环境摘要、结果、reviewer、时间 |
| `commands.log` | 实际执行命令与退出码 |
| `result.json` | 机器可读结论 |
| `junit.xml` | 测试结果；无测试则写 `N/A` |
| `hashes.sha256` | 目录内产物摘要 |
| `review.md` | 独立评审结论与残余风险 |
| `redaction-check.txt` | 敏感扫描结果 |

规则：

1. 原始敏感证据不进仓库，只存受限存储并在 manifest 写引用。
2. 截图、日志、报告必须脱敏；不得出现凭据、IP、用户名、原始串口或原始音频。
3. 目录只由所属波次写入；其他波次只读。
4. 证据 manifest 哈希可复算；不可复算的证据不算 PASS。
5. 云端同步只同步已脱敏、已评审、属于当前里程碑的证据。

### 14.2 完成标准

一个波次只有同时满足以下条件才算完成：

1. 该波所有 DoD 条目有证据。
2. QG 门通过，reviewer 独立签署。
3. 进度表即时更新，无批量补记。
4. 共享文件按所有权与合并顺序处理。
5. 无未登记阻塞；有阻塞则标 `BLOCKED`，不得写 `已完成`。
6. 敏感扫描通过。
7. 若是 W7 及以后，A-0 硬门在涉及真实节点、真机、部署或恢复的范围内已满足。

### 14.3 STOP 条件

出现以下任一情况，立即停止当前波次，不得“先做完再补”：

1. P1 或 P2 未冻结却要进入 W6 或 W0。
2. P3-07 或 P4-08 未冻结却要进入 Phase 5 或 Phase 6。
3. 工具链 ADR 未关闭。
4. 契约冲突或字段语义不明，且无契约变更记录。
5. 发现节点或 UI 在写判定。
6. 发现凭据、密钥、IP、用户名、原始串口或原始音频进入文档、日志、证据或提交。
7. 证据摘要不可复算或 manifest 与实际不符。
8. 迁移无备份、无回退或前向修复方案。
9. 共享文件被非所有者修改。
10. A-0 未通过却要声称真实节点、T5/T6、L3 至 L5、部署或恢复证据。
11. TCL profile 未生成却向用户索要 profile、规则、脚本或参数。
12. 适配器打开 COM5/COM7，或把唤醒时长当成正式通过条件。
13. 门禁被跳过，尤其是 G1、G5、G6。
14. 质量门失败仍继续合并。
15. 云端同步前未做敏感扫描。
