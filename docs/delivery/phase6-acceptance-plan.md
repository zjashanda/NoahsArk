## 1. 目的与判读规则

Phase 6 只做一件事：把已实施的东西按层级证明一遍，并留下可复算、可审计、可归档的证据。

1. “必须”“不得”是执行约束，不是已完成的声明。
2. 任何 `PENDING`、`IN PROGRESS`、`RECOMMENDED` 都不得被下游当成已冻结事实。
3. 没有 `run_id`、`manifest`、`verdict`、`verification` 的结论一律写成“未验证”，不得写成通过。
4. 层级之间不可替代：L1 不证明链路，L2 不证明真机，L3 不证明正式判定，L4 不证明业务闭环。
5. 同一事实在不同表中出现时，以 `docs/contracts/` 冻结值为准；本文只做引用，不做二次定义。

## 2. 分层定义与进入退出

L0 是文档与契约一致性，属于 P6 的隐含前提，不单独作为 P6 交付层。P6-01 的“L1 静态与契约”把 L0 的核对结果作为进入条件，合并执行。

| 层级 | 主计划 | 测试层 / mode | 进入条件 | 退出条件 | 必需证据（判定用） | 不得声称 |
|---|---|---|---|---|---|---|
| L1 静态与契约 | P6-01 | T1/T2，`static` | P4-08 冻结；代码可构建；契约候选可校验 | 静态检查、类型检查、契约校验、拒绝路径、迁移升降级全部有结论 | `execution_log`、`manifest`、`human_note`（评审签署） | 设备可用、音频链路可用、会话可用 |
| L2 模拟链路 | P6-02 | T3 `static`；T4 `smoke`（模拟） | L1 通过；控制面可在本地多进程运行；假节点可注入故障 | 门禁、判定、断线、STOP、对账、释放、恢复在模拟环境均有结论 | `execution_log`、`manifest`、`receipt`（模拟）、`anomaly_event`（注入时） | 真机时序、真实音频、真实释放 |
| L3 真机烟测 | P6-03 | T5，`smoke` | L2 通过；A-0 硬门通过；真实节点与 DUT 在场；无待处理 STOP | 独立 smoke run 跑通，证据可校验，清理事实可读 | `execution_log`、`serial_log`、`raw_audio`、`manifest`、`receipt` | 样本代表性、正式 PASS |
| L4 正式采样 | P6-04 | T6，`formal` | L3 通过；修订已批准；样本、阈值、重试、预算已批准；资源复检通过 | 每个 case 有五轴与 decision；分母可重建；Linux 复核完成；P0 关闭 | `raw_audio`、`device_log`（必需切片）、`serial_log`、`execution_log`、`manifest`、`anomaly_event`（发生时）、`linux_log_read`（依赖远程读取时） | 其他设备或固件成立、长期稳定 |
| L5 业务闭环 | P6-05 | T6 + L5 补充 | L4 通过；第二任务已批准；报告与知识规则已冻结 | 第二任务复用、14 章节报告、知识审阅、审计链均有结论 | L4 全部 + `human_note`（复用评审） | 跨项目泛化、未纳入设备 |

**跨层硬规则**：

1. 每层使用独立 `run_id`；`static` 只对应 L1/L2，`smoke` 只对应 L2/L3，`formal` 只对应 L4/L5。
2. 上一层未退出时，下一层只能准备环境，不得产出结论。
3. 任一层出现 P0 缺陷，后续层立即停止，不得“先跑完再修”。

## 3. L1 静态与契约验收（P6-01）

执行项：

| # | 检查 | 通过标准 | 失败时 |
|---|---|---|---|
| 1 | 构建与依赖 | 锁定文件可复现安装；构建无警告升级为错误 | `BLOCKED`，不得进入 L2 |
| 2 | 静态检查 | lint、类型检查、格式检查全部通过 | `FAIL`，P2 起 |
| 3 | 契约 schema | OpenAPI、事件 envelope、manifest、verdict、TaskCard schema 可校验 | `BLOCKED`，契约缺口 |
| 4 | 拒绝路径 | 未知 schema、未知枚举、越权、重复幂等键、跳门请求均被拒绝 | `FAIL`，按 P1 处理 |
| 5 | 迁移 | 空库与种子库可升级、可回退；已应用迁移未被编辑 | `BLOCKED`，数据风险 |
| 6 | 权限矩阵 | 节点令牌无权写判定表；UI 无写权威状态路径 | `FAIL`，按 P0 处理 |
| 7 | 敏感扫描 | 无口令、私钥、令牌、地址、真实序列号 | `BLOCKED`，先清理再继续 |
| 8 | UI 构建 | 冻结设计对应路由可构建；无裸色值；控制台零错误 | `FAIL`，按 P1 处理 |

退出判据：8 项全部有机器可读结论，且每项结论都能回到命令、退出码和产物摘要。任一 `BLOCKED` 项存在时，L1 只能标记“阻塞”，不得标记“部分通过”。

## 4. L2 模拟链路验收（P6-02）

模拟层只证明“规则和顺序是对的”，不证明“设备和时序是对的”。假节点、假回执、假清理必须带 `evidence_origin=simulated`，且永不计入正式分母。

| ID | 场景 | 注入方式 | 预期结论 | 必需证据 |
|---|---|---|---|---|
| S-01 | 门禁顺序 | 跳过 G2 直接请求 G5 | 拒绝推进，返回当前 gate，不产生 run | 门禁事件、拒绝审计、状态快照 |
| S-02 | 缺批准派发 | 批准缺失或快照不匹配时请求派发 | `BLOCKED`，`failure_class=blocked` | 批准查询结果、派发拒绝记录 |
| S-03 | 断线续跑 | 运行中切断假节点通道 | 本地继续；控制面 `OFFLINE`；占用保持；不新派 | 心跳时间线、占用快照、run 继续记录 |
| S-04 | STOP-first | 断线期间下发 STOP 后重连 | 依六步执行：STOP、停后续动作、补传、去重、对账、恢复领取 | 六步时间线、STOP ACK、去重统计 |
| S-05 | 旧 epoch | 旧节点携带 `epoch < current` 提交回执 | 拒绝，不改变当前运行、租约、占用 | 拒绝审计、epoch 对比 |
| S-06 | 重复上传 | 相同 `evidence_id + chunk_index + digest` 重复到达 | 幂等去重，计数不重复；同 ID 不同摘要转冲突 | 上传幂等记录、冲突记录 |
| S-07 | 摘要不符 | 篡改必需证据字节 | `CONFLICTED`，`BLOCKED/invalid-evidence` | 双方摘要、重算日志、隔离记录 |
| S-08 | 缺清理回执 | 停止确认但无回执 | 释放 `held`，设备保持占用，证据完整性独立计算 | 占用快照、回执缺失记录 |
| S-09 | 清理失败 | 回执 `cleanup_status=failed` | `quarantined`，拒绝释放，`NEEDS_REVIEW` | 失败回执、隔离记录、复核记录 |
| S-10 | 控制面重启 | 运行中重启控制面进程 | 按数据库、manifest/摘要、占用对账顺序恢复；不重复建 task/run | 恢复日志、对账差异、ID 前后对照 |

退出判据：10 个场景均有 `decision` 与证据，且失败注入后的拒绝路径与 `evidence-verdict.md` §14.2 派生顺序一致。模拟通过只能写“L2 结论”，不得写“链路可用”“真机通过”。

## 5. L3 真机烟测与设备链路（P6-03）

设备前置：

| 项 | 要求 | 不满足时 |
|---|---|---|
| DUT 与固件 | 设备身份按 run 绑定，不使用友好名；固件在白名单内（候选 `V038`） | `BLOCKED`，不刷写、不降级 |
| 串口 | COM3/COM4 只读可读，时间线可对齐 | `BLOCKED` |
| 串口负向 | COM5/COM7 不得被打开；打开即判失败 | `FAIL`，按 P1 处理 |
| 音频端点 | 稳定 `endpoint_id`，历史 Unknown 端点不得使用 | `BLOCKED` |
| 会话 | 交互式会话可用，非 Session 0 直跑音频 | `BLOCKED` |
| 存储 | D: 剩余空间高于预警阈值，且不得低于保护阈值；容量未知时不得默认充足 | `BLOCKED` |
| 队列 | 无待处理 STOP，无残留占用 | `BLOCKED` |
| 节点通道 | 仅出站长轮询，无入站管理端口 | `BLOCKED` |

执行要求：

1. 烟测是 `mode=smoke` 的独立 run，样本为 `smoke_min`，不进入任何分母。
2. 至少覆盖一次完整链路（领取、执行、采集、上传、清理、回执）和一次负向检查（COM5/COM7 未打开、端点身份未漂移）。
3. 原始音频、串口日志、执行日志必须能按 case 关联，且摘要可复算。
4. 清理事实必须可从回执或白名单日志读出；读不出时写 `unknown`，不得推测。

退出判据：烟测 run 有 `mode_outcome`，证据 `COMPLETE`（或明确列出缺失项），节点与设备事实可核对。L3 不给 `business_verdict=PASS`，也不产生 `formal_pass`。

## 6. L4 正式采样与 Linux 独立判定（P6-04）

进入条件（全部为真才可开始）：

| 条件 | 检查 | 证据 |
|---|---|---|
| L3 已退出 | 烟测结论存在且无 P0 | 烟测报告 |
| 修订已批准 | 批准范围摘要与 `bundle_digest` 一致 | 批准快照 |
| 样本已批准 | 样本量、通过率、重试、预算在冻结修订中显式选定 | 修订快照 |
| 资源复检 | 设备、端点、存储、时钟、租约重新检查通过 | 复检记录 |
| 无残留 | 无待处理 STOP，无他人占用 | 占用快照、STOP 队列 |

判定组合（与 `domain.md` §14 一致，逐 case 记录）：

| 情形 | 五轴 | decision | 分母 |
|---|---|---|---|
| 正常通过 | `COMPLETED / VALID / PASS / COMPLETE / PASS` | `PASS` | 计入 |
| 有效失败 | `COMPLETED / VALID / FAIL / COMPLETE / PASS` | `FAIL` | 计入 |
| 输入无效 | `COMPLETED 或 ABORTED / INVALID / NOT_EVALUATED / COMPLETE 或 INCOMPLETE / NOT_RUN` | `INVALID` | 不计入 |
| 环境阻断 | `ABORTED 或 BLOCKED / BLOCKED / NOT_EVALUATED / UNVERIFIED / NOT_RUN` | `BLOCKED` | 不计入 |
| 证据不完整 | `COMPLETED / VALID 或 UNKNOWN / NOT_EVALUATED / INCOMPLETE / NOT_RUN` | `BLOCKED` | 不计入 |
| 停止 | `ABORTED / UNKNOWN / NOT_EVALUATED / 视情况 / NOT_RUN` | `STOPPED` | 不计入 |
| 复核未通过 | 五轴其余成立但 `verification_status != PASS` | `NEEDS_REVIEW` | 暂不计入 |
| 重试通过 | 新 attempt 五轴通过，首次保留 | 首次按原分类 | 首次按原分类计入或不计入，重试单列 `FLAKY_SUSPECT` |

正式 PASS 的 11 项前置（`approval_valid`、`boundary_frozen`、`mode_formal`、`execution_completed`、`sample_valid`、`business_pass`、`required_evidence_complete`、`digest_verified`、`linux_review_pass`、`no_blocking_anomaly`、`denominator_eligible`）缺一不可。只满足五轴而缺 `decision=PASS`、`formal_pass=true`、`failure_class=none` 或分母资格时，只能写“轴一致”。

Linux 独立复核必须完成四步：重算摘要、重建实体关联、复评分母、复评 oracle 结果。复核人不得是本次运行的执行者或节点侧人员；复核记录独立存放，不得由节点回执替代。节点自报 `PASS` 一律 `used_for_decision=false`。

退出判据：

1. 每个计划 case 都有五轴、`decision`、`failure_class`。
2. 分母可由样本明细重建，排除项逐条有原因。
3. 所有正式 `PASS` 都有完整证据与复核记录。
4. P0 缺陷为零；P1 有结论或书面风险接受。

## 7. L5 业务闭环与知识复用（P6-05）

L5 证明“平台能支撑第二个真实任务并复用经验”，不证明“跨项目管理能力”。

| 检查 | 通过标准 | 证据 |
|---|---|---|
| 第二任务 | 独立 task/revision，不复用第一任务运行 | 任务谱系、修订谱系 |
| 复用与审阅 | 候选显示来源、适用条件、未审核状态；未审阅不得作为结论依据，推广需授权审阅 | 复用事件、候选详情、审阅记录 |
| 报告 | 14 个 `category` 全部出现，缺失写 `EMPTY` 或 `NOT_APPLICABLE` | `report.json`、`evidence-index.json` |
| 记录分离 | 自动判定与人工补充分列，人工记录不得表述为自动 PASS | 报告章节 `human_supplements` |
| 展示一致 | UI 展示与后端权威状态一致，投影可重建 | 一致性核对表、重建记录 |
| 审计 | 原始材料读取、导出、复用均逐次审计 | `audit/*.jsonl` |

退出判据：第二任务有独立结论，知识复用有来源与适用性说明，报告章节齐全，审计链完整。L5 报告不得写“知识已推广”除非有审阅记录。

## 8. 结果分类：PASS、FAIL、BLOCKED

验收标签只有三类，且必须能从 `decision` 机械映射，不允许人工解释。

| 验收标签 | 允许的 `decision` | 定义 | 分母 | 允许写法 | 禁止写法 |
|---|---|---|---|---|---|
| `PASS` | `PASS` | 11 项前置全部成立，证据与复核齐全 | 计入 | “case 通过，证据可复算” | “应该没问题”“基本通过” |
| `FAIL` | `FAIL`（`valid-failure`） | 输入有效、证据完整、业务未达预期 | 计入 | “有效失败，计入分母” | “环境问题”“再跑一次就好” |
| `BLOCKED` | `BLOCKED`、`INVALID`、`STOPPED`、`NEEDS_REVIEW`、`NOT_EVALUATED`、`NOT_APPLICABLE` | 不构成业务结论，或结论尚未成立 | 不计入 | “阻塞，原因码 X，解除条件 Y” | “暂不统计”“忽略此项” |

补充规则：

1. `BLOCKED` 必须在报告中写明 `failure_class` 与解除条件，否则视为信息缺失。
2. `NEEDS_REVIEW` 不是通过的近义词；复核完成前不得进入分母，也不得对外表述为通过。
3. `INVALID`、`STOPPED`、`infra-error` 不得改写成 `FAIL`，`FAIL` 也不得改写成环境问题。
4. 无证据不 PASS，无复核不 PASS，无分母资格不 PASS；报告通过率的分母只能是有效正式样本，分子只能是 `decision=PASS`。

## 9. 恢复演练（P6-06）

恢复演练独立于功能验收。演练不是“演示一次”，而是按注入、观察、对账、记录四步留痕。任一项未演练，相关能力只能写“未验证”。

| ID | 演练 | 注入 | 通过判据 | 必需证据 | 失败即 |
|---|---|---|---|---|---|
| D-01 | 断线续跑 | 已启动正式 run 中断开节点通道 | 本地继续执行；设备保持 `OCCUPIED`；`execution_permit=GRANTED`；不新派、不重播、不重复采样 | 心跳时间线、占用快照、run 继续记录 | P0，停止后续演练 |
| D-02 | STOP-first 重连 | 断线期间创建 STOP 请求后重连 | 严格六步顺序；迟到 STOP 不改写已执行动作 | 六步时间线、STOP ACK、去重统计 | P0 |
| D-03 | 对账 | 重连后存在部分上传、重复回执、旧 epoch | 去重正确；对账完成前不重派；旧 epoch 不取得执行权 | 对账报告、差异清单、epoch 对比 | P1 |
| D-04 | 设备释放 | 运行结束但大日志未归档、判定未完成 | 满足 `local_stop_confirmed`、`safe_cleanup_done`、`occupancy_reconciled` 即可释放；证据继续上传 | 释放回执、占用对账、后续上传记录 | P1 |
| D-05 | 控制面恢复 | 控制面进程或主机重启 | 按数据库、manifest/摘要、任务运行设备占用对账顺序恢复；不重复建实体 | 恢复日志、对账差异、ID 前后对照 | P0（顺序错误亦 P0） |
| D-06 | 备份恢复 | 从备份重建数据库与证据索引 | 数据可读、摘要可复算、占用可对账、审计连续 | 演练报告、复算记录、耗时记录 | P0 |

演练规则：

1. 断线只改变可见性，不改变占用与执行许可；恢复顺序固定为数据库、manifest/摘要、占用对账，顺序错误视为流程缺陷。
2. 租约到期不等于设备所有权到期；缺 `cleanup_receipt` 只阻塞释放，不阻塞证据完整性，也不自动阻塞 PASS。
3. `cleanup_status=failed` 进入 `quarantined`，人工恢复前不得再分配。
4. RPO/RTO 只在 D-06 有完整时间记录时填写具体值；否则只能写“未验证”，不得给出估算值、目标值或行业参考值。
5. 备份“可远程按需读取”不算备份，必须有一次真实恢复。

## 10. 缺陷处理

| 等级 | 定义 | 示例 | 立即动作 | 分母处理 | 关闭条件 |
|---|---|---|---|---|---|
| P0 | 结论失真或安全边界被突破 | 假 PASS、越权读取、证据丢失、重复执行、跨设备污染、恢复顺序错误 | 停止验收，隔离环境与证据，通知所有者 | 相关样本全部不计入 | 修复、独立复现失败、受影响层重跑 |
| P1 | 结论可用性受损 | 错误分类、状态不一致、分母错误、释放与判定混淆 | 停止相关场景，保留现场 | 受影响样本暂不计入 | 定向回归加全链路复跑 |
| P2 | 功能可用但有缺陷 | 提示不清、非阻断展示错误、可访问性缺口 | 记录并继续其他场景 | 视是否影响判定 | 修复后回归该场景 |
| P3 | 文档与体验建议 | 文案、排版、术语不一致 | 记录，不阻断 | 不影响 | 纳入后续版本 |

修复与回归：

| 动作 | 触发 | 要求 | 证据 |
|---|---|---|---|
| 重测 | 单点失败且原因明确 | 新建 attempt，不覆盖首次结果 | 两次 attempt 独立证据 |
| 回归 | P0/P1 修复后 | 覆盖原失败点、相邻路径、同层全链路 | 回归报告、失败用例清单 |
| 返工 | 设计或契约级缺陷 | 回到对应阶段修订，不在验收期改契约 | 变更记录、重新冻结记录 |
| 复评 | 复核未通过 | 由不同复核人重做四步复核 | 新 `verification_id` |
| 风险接受 | P1 无法在窗口内关闭 | 书面说明影响、范围、有效期、接受人 | 风险接受记录 |

退出条件：

1. P0 全部关闭，且关闭有复现失败证据。
2. P1 有结论，或有明确范围与有效期的书面接受。
3. 返工后受影响的 L 层级已重跑，旧结论标记为“已被替代”，不得删除。
4. 缺陷单、回归记录、残余风险、未关闭项与报告一致，未关闭项标注是否阻断签收。
