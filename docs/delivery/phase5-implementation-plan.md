### 2.1 切片与全量实现的差距

| 维度 | 切片当前能力 | 全量实现要求 | 差距性质 |
|---|---|---|---|
| 数据 | fixture 形状的 seed 数据 | 真实任务、修订、运行、证据 | 数据来源替换，不是改表结构 |
| 身份 | 开发期角色请求头 | 会话、角色、最小权限、服务身份 | 安全机制缺失 |
| 证据 | 索引与 manifest 元数据 | 内容寻址载荷、摘要复算、保留与访问审计 | 存储层缺失 |
| 判定 | 五轴列与 fail-closed 约束 | 判定引擎、独立复核、正式分母 | 规则引擎缺失 |
| 运行 | 无编排 | 派发、租约、epoch、占用、STOP、对账 | 状态机缺失 |
| 节点 | 无 | Node Agent、spool、执行器、清理回执 | 整条链路缺失 |
| UI | fixture 演示 | 按冻结设计实现的真实界面 | 需等 P1-08 |
| 运维 | 本机启动 | 反向代理、TLS、备份、恢复演练、监控 | 需等 P2-07 与 A-0 |
| 证据包 | 无 | 每波 manifest、命令日志、独立评审 | 流程未执行 |

切片是加速器，不是里程碑。它可以反哺 P2-01、P2-02、P2-03、P2-05 的决策，但不能替代 Phase 2 冻结，也不能把 S0 至 S2 记成 P5-01 至 P5-04 完成。

## 8. 变更控制与回滚

### 8.1 变更控制

| 变更类型 | 示例 | 批准 | 记录 | 回滚 |
|---|---|---|---|---|
| 契约变更 | 新增字段、改枚举、改错误码 | R-CON | 契约变更记录与新版本号 | 拒绝合并消费方，保留旧读取器 |
| 迁移变更 | 新表、新索引、改约束 | 数据所有者 | 迁移文件与新 revision | 前向修复；破坏性回退需已验证备份 |
| 共享文件变更 | 锁文件、组合根、CI 基线 | 该文件所有者 | 变更说明与合并序号 | 停止合并，所有者裁决后重放 |
| 判定规则变更 | 五轴组合、fail-closed 条件 | 判定所有者与独立评审 | 规则版本与判定矩阵快照 | 旧版本继续生效，历史判定不回写 |
| 阈值变更 | 租约、心跳、spool 上限、retention | 配置所有者 | 配置版本与生效时间 | 恢复上一配置版本并审计 |

| 工期变更 | 估算回填、关键路径调整 | 主控 | 估算依据与实际数据 | 保留旧估算，新版本另记 |

### 8.2 回滚分级

| 级别 | 场景 | 动作 | 禁止 |
|---|---|---|---|
| L1 部署回滚 | 新版本上线后异常 | 回退到上一构建，保留数据库 | 回退已冻结修订、已接收证据、审计记录 |
| L2 迁移修复 | DDL 失败或数据异常 | 优先前向修复；必要时用已验证备份恢复 | 无备份的破坏性 downgrade |
| L3 判定回退 | 判定规则错误或证据不符 | 受影响判定转 `NEEDS_REVIEW`，写补偿审计，独立复核后重判 | 直接改历史判定行 |
| L4 波次回退 | 某波 QG 失败且短期无法修复 | 停止后续波次，保留已完成证据，状态改 `BLOCKED` 或 `返工` | 用后续波次掩盖前一波失败 |

全局规则：回滚部署，不回滚历史；投影与读模型可丢弃重建；任何触及判定的回滚必须有审计与复核；触发条件必须来自可观测证据。

## 9. 进度台账与波次报告

### 9.1 台账字段

台账写入既有 `.omo/ulw-execute/ledger.jsonl` 与 `docs/delivery/construction-progress.md`，不新建平行进度文件。

| 字段 | 说明 |
|---|---|
| `item_id` | 主计划编号加波次序号，例如 `P5-03-W2-01`；纵切用 `VS-` 前缀 |
| `phase` | Phase 3、Phase 5、Phase 6、Final 或 Release |
| `wave` | W0 至 W10 |
| `task` | 可验收的单一工作单元 |
| `owner_role` | 岗位，不写人名；未分配写 `待分配` |
| `reviewer` | 独立评审岗位，不得与 owner 相同 |
| `status` | 待分配、已派发、进行中、待验证、已完成、阻塞、返工、取消 |
| `dependencies` | 前置 item_id 或门 |
| `start_utc`、`end_utc` | 实际时间，UTC |
| `gate` | QG-W0 至 QG-W10 或 DG 门 |
| `evidence_path` | 证据目录或 manifest 路径 |
| `blocker` | 原因与责任方；无则写 `无` |
| `rework`、`retry_count` | 返工原因与次数、重试次数 |
| `merge_order` | 共享文件合并序号或 `N/A` |

更新规则：

1. 每个工作单元完成后立即写入，不得批量补记。
2. `已完成` 必须有 `evidence_path` 与 reviewer；缺一只能写 `待验证`。
3. `阻塞` 必须写责任方与解除条件，不得用“等待中”代替。
4. 返工保留原记录，新尝试用新 ID。
5. 台账不写凭据、地址、用户名、原始串口或原始音频。
6. 台账不修改主计划复选框。
7. 纵切条目与平台波次分开登记，不得把 `VS-S2` 写成 `P5-04` 完成。

### 9.2 波次报告格式

```text
WAVE: W0..W10
DONE: 本波完成的可验收单元，逐条对应 item_id
VERIFY: 命令 -> 实际结果（含失败用例）

RISKS: 新增或变化的阻塞，责任方，解除条件

CLAIMS: 明确本波不声称的事项
```

报告不得出现“全部完成”“生产可用”“已冻结”等无证据措辞。`CLAIMS` 段为必填，防止上下文丢失后误读。
