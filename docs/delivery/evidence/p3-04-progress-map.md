## 4. 进度字段

每条记录必须有下列 10 个字段，缺一不得写入台账。

| 字段 | 必填 | 取值与规则 |
|---|---|---|
| `item_id` | 是 | 主计划 ID 或波次内任务 ID，例如 `P5-03-W2-01`；拆分任务用执行项序号加波次 |
| `phase` | 是 | `Phase 3`、`Phase 5`、`Phase 6`、`Final`、`Release` |
| `wave` | 是 | `W0` 至 `W10`；非波次填 `N/A` |
| `task` | 是 | 单一可验收工作单元，不写合并目标 |
| `status` | 是 | 见 §5 的七个取值之一 |
| `owner_role` | 是 | 施工方案 §4.0 的 `R-ARCH`、`R-CON`、`R-BE`、`R-NODE`、`R-FE`、`R-QA`、`R-OPS`、`R-SEC`、`R-REV`、`R-PM`；未分配写 `待分配` |
| `dependency` | 是 | 前置 `item_id`、门（DG/QG）或 `无`；必须来自 WBS §1 或主计划，不得自行发明 |
| `evidence` | 是 | `docs/delivery/evidence/**` 下的相对路径或 manifest；没有写 `无` |
| `blocked_reason` | 是 | 阻塞原因、责任方、解除条件；无阻塞写 `无`，不得写“等待中” |
| `updated_at` | 是 | UTC 时间戳，精度到分钟，例如 `2026-10-29T13:01Z` |

扩展字段沿用施工方案 §12：`reviewer`、`gate`、`start_utc`、`end_utc`、`rework`、`retry_count`、`merge_order`。可空，但 `status=已完成` 时 `reviewer` 不得为空且不得等于 `owner_role`。

## 5. 状态标记

| 标记 | 状态 | 判定条件 |
|---|---|---|
| `[ ]` | 待分配 | 无 owner 或无进入条件，未产生任何产物 |
| `[>]` | 已派发 | 有 owner 与 `start_utc`，尚无可用产物 |
| `[.]` | 进行中 | 已产出部分文件，未达退出条件 |
| `[?]` | 待验证 | 产物存在，独立评审或复算未完成 |
| `[~]` | 阻塞 | 存在外部或门禁阻塞，必须在 `blocked_reason` 写明责任方与解除条件 |
| `[!]` | 返工 | 验证失败需重做，保留原记录并追加新尝试 |
| `[x]` | 已完成 | 有 `evidence`、有独立 `reviewer`、退出条件逐条满足 |

`[~]` 只用于阻塞。被阻塞不等于失败，也不等于取消；解除后回到 `[.]` 或 `[?]`。

## 6. 更新规则

1. 只在取得证据后写 `[x]`；先写 `[?]`，评审通过再改 `[x]`。没有证据的“完成”一律退回 `[?]`。
2. 一个工作单元完成后立即登记，不得批量补记；时间戳取实际动作时间，不回填想象时间。
3. 不重复计数：`P5-03` 只在执行项 18 计数，`P5-05` 只在执行项 20 计数，`P5-11` 只在执行项 26 计数。辅助行存在是为了记录实际工作量，完成判定仍以主计数行的双波退出为准。
4. 阻塞写 `[~]` 并给出责任方与解除条件；责任人未明确时不得把状态写成 `[.]`。
5. 返工不覆盖历史：原行保留，新增一行并递增 `retry_count`。
6. 台账不修改主计划复选框，也不修改执行计划 TODO；两者由主控单独勾选。
7. 纵切任务用 `VS-` 前缀另册登记，不混入 W 波次。
8. 台账不写凭据、IP、用户名、原始串口、原始音频或未脱敏日志。
