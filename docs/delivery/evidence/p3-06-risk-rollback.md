## 0. 判读规则

1. 风险 ID 采用 `RX-<类>-<序号>`，类为 TECH/DEV/DATA/SEC/SCHED/NET；行末 `源` 列指向施工方案 §10 的 `R-xx` 或实施计划 §10 的 `R-xx`，未映射的标 `新增`。
2. “触发”必须是可观测事实（命令退出码、扫描命中、日志字段、状态值），不得写成主观判断。
3. “回滚”只允许施工方案 §10 全局回滚规则允许的动作：回滚部署不回滚历史、迁移优先前向修复、投影可重建、触及判定必须有审计与独立复核。
4. owner 只写角色代号（施工方案 §4.0）。每条风险在登记时必须同时有 owner 与 reviewer，二者不得相同。
5. 全部风险行当前状态为 `OPEN·未演练`。演练通过的判定见 §4，未演练不得在 P3-07 写“已验证”。

## 2. STOP 条件

以下任一出现，立即停止当前波次，不得“先做完再补”。触发行人须在台账写 `阻塞`、责任方与解除条件。

| # | STOP 条件 | 可观测判据 | 解除条件 |
|---|---|---|---|
| S-01 | 契约冲突或字段语义不明 | 两条规则对同一字段给出不同含义，或实现需自行解释且无契约变更记录（`docs/contracts/domain.md` §21 未决项被当作已定） | R-CON 出变更记录与新版本号，独立复核后重新派发 |
| S-02 | 迁移失败 | `alembic upgrade head` 非零退出；`alembic heads` 多 head；downgrade 无备份 | 前向修复 revision 通过空库与种子库双跑；备份经恢复验证 |
| S-03 | 秘密暴露 | 秘密扫描命中；文档/日志/证据/提交出现凭据、密钥、令牌、IP、用户名 | 泄露物已清除；操作方完成轮换；事件记录归档 |
| S-04 | 触及真实设备或真实凭据但门未开 | A-0 未过、G-TCL 未决、却存在真机执行或凭据读取痕迹 | A-0 事实清单关闭；真机时间窗与授权单独记录 |

## 3. 回滚规则

1. **禁止破坏性 git 操作。** 不用 `reset --hard`、`clean -fdx`、强推、改写历史、`rebase` 覆盖他人分支。回滚以新增提交或恢复已验证备份表达；证据目录与迁移文件不从工作区直接删除。
2. **迁移只前向修复。** 优先新增 revision 修正；破坏性 downgrade 必须有已验证备份与数据所有者批准，并在证据目录记录备份位置与恢复验证结果。已应用迁移永不编辑。
3. **保留证据。** 回滚不删除证据目录、manifest、`commands.log`、审计行。作废的判定改 `NEEDS_REVIEW`，作废的证据目录原地保留并标 `VOID`，不覆盖 digest。
4. **回滚部署，不回滚历史。** 冻结 Revision、已接收证据、审计记录不可改写；补偿以新记录表达。
5. **投影可丢弃重建。** 读模型、报告、TaskCard 可整表重建；重建后须零差异。
6. **触及判定必须有审计与独立复核。** 回滚方不得同时是复核方。
7. **回滚触发必须来自可观测证据。** 不得事后主观判断“看起来不对”就回滚。
8. **回滚分级**：L1 部署回滚（保留数据库）、L2 迁移前向修复、L3 判定转 `NEEDS_REVIEW`、L4 波次转 `阻塞`/`返工`（见实施计划 §8.2）。
