## 0. 使用方式

1. 本手册是现场作业脚本，不是验收结论。所有"应""必须"都是待执行的约束。
2. 每完成一条，写"做了什么、命令、退出码、产物路径、结论"，不写"应该没问题"。
3. 任一步骤的前置不成立时，该步只能记 `BLOCKED` 并写解除条件，不得跳过继续。
4. 术语与判定口径以 `phase4-acceptance-plan.md` §7 和契约冻结值为准，本文不复述、不改写。上游 `P3-07`、`P4-08` 未冻结时，本手册只能用于演练准备，不得产出正式结论。

## 1. 环境准备与 preflight 检查清单

### 1.1 开始前必须落盘的五个输入

| 输入 | 内容 | 缺失时 |
|---|---|---|
| 版本清单 | 被测版本、构建号、部署记录、回滚包位置 | `BLOCKED`，不得开始 |
| 契约冻结件 | 版本号与哈希、schema、枚举、错误码 | `BLOCKED`，只能引用候选值做预演 |
| 批准快照 | 冻结 Revision、`bundle_digest`、批准范围与时间 | `BLOCKED`，不得执行 |
| 样本计划 | 样本量、通过率、重试预算、运行预算 | `SAMPLE_PLAN_UNDEFINED`，拒绝冻结 |
| 责任矩阵 | 每个角色具名责任人与替补 | `BLOCKED`，不得签收 |

### 1.2 preflight 分组检查

| 组 | 检查项 | 通过标准 | 记录形式 |
|---|---|---|---|
| 控制面 | PostgreSQL、证据存储、健康检查、时钟同步 | 健康检查通过，时间偏差在限内 | 健康检查输出，时钟偏差值 |
| 节点 | 服务账户、交互式会话、出站长轮询、spool 水位 | 无入站管理端口，spool 未预警 | 节点自检输出 |
| 设备 | 固件白名单、稳定 `endpoint_id`、COM3/COM4 可读 | 固件符合，端点身份稳定 | 端点枚举快照 |
| 串口负向 | COM5/COM7 未被打开 | 全程未打开 | 端口占用记录 |
| 音频 | 采集与回放端点绑定、校准记录 | 绑定稳定身份，校准可查 | 端点与校准记录 |
| 存储 | 证据盘可写，容量高于保护阈值 | 容量记录可查，未低于保护线 | 容量快照 |
| 队列 | 无残留占用、无待处理 STOP | 占用为空，STOP 队列为空 | 占用快照与 STOP 队列 |
| 备份 | 数据库、manifest、证据存储有可恢复副本 | 有一次真实恢复记录 | 演练报告与对账差异 |
| 权限 | 角色、任务关系、证据访问最小化 | 越权用例可构造 | 权限矩阵与审计样本 |
| 安全 | 无凭据、令牌、序列号进入工作目录 | 敏感扫描零命中 | 扫描输出 |

### 1.3 preflight 结论口径

- 全组通过：写 `PREFLIGHT_PASS`，附检查时间、执行人、产物摘要。
- 任一组不通过：整份 preflight 记 `PREFLIGHT_BLOCKED`，列出组名、失败项、解除条件、责任人。不得写"基本可用"。
- L3 起额外要求人工门 H-01 通过；H-01 未过时 L3、L4、L5 全部 `BLOCKED`。
- preflight 结果当天有效。跨日重跑必须在结果中写明的 UTC 时间戳。

## 2. 执行顺序：L1 → L5

顺序固定，不得倒置，不得并行产出结论。上一层未退出时，下一层只能做准备。

| 步 | 层级 | 模式与测试层 | 进入条件 | 退出判据 | 关键产物 |
|---|---|---|---|---|---|
| S1 | L1 静态与契约 | `static`，T1/T2 | preflight 通过，代码可构建 | 8 项检查各有机器可读结论，无 `BLOCKED` | 命令日志、契约校验、迁移记录 |
| S2 | L2 模拟链路 | `static` / 模拟 `smoke`，T3/T4 | L1 退出 | S-01 至 S-10 均有 decision 与证据 | 模拟执行日志、注入记录、模拟回执 |
| S3 | L3 真机烟测 | `smoke`，T5 | L2 退出，H-01 通过，设备在场 | 独立 smoke run 跑通，证据可校验 | 原始音频、串口日志、执行日志、清理事实 |
| S4 | L4 正式采样 | `formal`，T6 | L3 退出，H-03 通过，资源复检通过 | 逐 case 五轴与 decision 齐全，分母可重建，P0 为零 | 正式证据、verdict、verification |
| S5 | L5 业务闭环 | `formal` + 补充，T6 | L4 退出，第二任务已批准 | 复用有来源，14 章节报告齐全，审计链完整 | 复用记录、报告、审阅记录 |

跨步硬规则：

1. 每层使用独立 `run_id`，`static`、`smoke`、`formal` 不跨层复用。
2. S3 的 smoke 样本永不进入 S4 分母；S4 的历史重放不计新样本。
3. 任一步出现 P0，立即停止后续步骤，已产出结论保留并标"受 P0 影响，待重跑"。
4. 每步结束写一行交接记录：层级、run_id、结论、未决项、下一步是否放行。
5. S6 汇总与归档在 S5 退出后执行，不在中途并行。

## 3. 证据采集、命名、存储与保留

### 3.1 采集最小集

| 类别 | 内容 | 关联键 |
|---|---|---|
| 运行事实 | run、attempt、case、起止时间、mode、层级 | `run_id`、`attempt`、`case_id` |
| 设备事实 | 设备身份、固件、端点、串口、音频通道 | `device_id`、`endpoint_id` |
| 输入 | 音频、语料、参数、回放记录 | `case_id`、`input_digest` |
| 原始证据 | 音频、串口、设备日志切片、截图 | `evidence_id`、`content_digest` |
| 结构化记录 | 执行日志、结果、异常、回执 | `manifest_id`、`receipt_id` |
| 判定 | 五轴、decision、failure_class、规则版本 | `verdict_id` |
| 复核 | 摘要重算、关联重建、分母复评、oracle 复评 | `verification_id` |
| 释放 | 本地停止、安全清理、占用对账 | `occupancy_id` |
| 访问 | 读取、导出、下载 | `audit_id` |

采集三条硬约束：UTC 时间不得回填；原始证据写入前重算摘要；节点自报事实只作为 `node_observed_*`，不替代 Linux 结论。

### 3.2 命名与目录

统一路径：`docs/delivery/evidence/phase6/<P6-id>/<level-id>/<UTC-timestamp>-<short-ref>/`。
原始音频与原始日志只存受限存储，仓库内只放引用、摘要与 `index.json`。

| 对象 | 规则 | 反例 |
|---|---|---|
| 时间戳 | `YYYYMMDDTHHMMSSZ` | `2026-10-29 15:11` |
| 证据文件 | `<evidence_id>__<sha256前12>__<name>.<ext>` | `唤醒测试最终版.wav` |
| 目录身份 | 小写 UUID，不用可读前缀当身份 | `run-最终版/` |
| 更正 | 新建证据项并标 `supersedes` | 覆盖原文件 |
| 禁止字符 | 空格、中文名、IP、序列号、令牌、真实姓名 | `192.168.x.x_capture.wav` |

每层目录必备 `manifest.json`、`commands.log`、`result.json`、`hashes.sha256`、`redaction-check.txt`，缺一即目录无效。L4 起追加 `review.md` 与 `index.json`。`junit.xml` 无自动化测试时写 `N/A`。

### 3.3 存储、保留与访问

1. 证据走内容寻址，`evidence_id` 与 digest 不得因归档而变化。
2. 30 天热存到期只标 `archive_pending`，不自动删除；无归档不删除。
3. 远程按需读取不算备份、不算归档。备份核对分数据库、manifest、证据索引、文件四路。
4. 原始材料按角色最小授权，逐次审计；越权请求拒绝并告警，不泄露对象是否存在。
5. 已接受证据不得原地替换，更正另立新项并保留原项。
6. 目录验收：能被独立重建，每个 `evidence_id` 可解析，每个 verdict 可回到证据与规则版本。

## 4. 失败处理与缺陷流程

现场处置顺序固定：保留现场 → 固定证据摘要 → 归类 → 决定是否重测 → 记录 → 通知责任人。禁止先清理现场再回忆。

### 4.1 分级与动作

| 等级 | 示例 | 立即动作 | 分母 | 关闭条件 |
|---|---|---|---|---|
| P0 | 假 PASS、越权、证据丢失、重复执行、跨设备污染、恢复顺序错误 | 停止验收，隔离环境与证据 | 相关样本全部不计入 | 修复、独立复现失败、受影响层重跑 |
| P1 | 错误分类、状态不一致、分母错误、释放与判定混淆 | 停止相关场景，保留现场 | 受影响样本暂不计入 | 定向回归加全链路复跑 |
| P2 | 提示不清、非阻断展示错误、可访问性缺口 | 记录并继续其他场景 | 视是否影响判定 | 修复后回归该场景 |
| P3 | 文案、排版、术语 | 记录，不阻断 | 不影响 | 纳入后续版本 |

### 4.2 缺陷单最小字段

编号、等级、发现层级与 run_id、复现步骤、期望与实际、证据引用、影响的分母与结论、责任方、解除条件、状态。缺任一项视为信息缺失，不得关闭。

### 4.3 重测、回归、返工、复评

| 动作 | 触发 | 必须留下的东西 |
|---|---|---|
| 重测 | 单点失败且原因明确 | 新 attempt 的独立证据，首次结果保持不可变 |
| 回归 | P0/P1 修复后 | 原失败点、相邻路径、同层全链路的回归记录 |
| 返工 | 设计或契约级缺陷 | 变更记录与重新冻结记录，不在验收期改契约 |
| 复评 | 复核未通过 | 不同复核人、新 `verification_id` |
| 风险接受 | P1 窗口内无法关闭 | 影响、范围、有效期、接受人，四项齐全 |

环境或基础设施故障归 `invalid-environment` 或 `infra-error`，不得写成 `valid-failure`。重试通过只标 `FLAKY_SUSPECT`，不覆盖首次结论。旧结论重跑后标"已被替代"，不删除。

## 5. 验收报告模板与角色职责

### 5.1 报告固定 14 章节

顺序与 `category` 名不得改：`summary`、`automated_checks`、`smoke`、`formal_records`、`human_supplements`、`deviations`、`completion_assessment`、`blockers`、`metrics`、`residual_risks`、`deliverables_reusable_assets`、`lessons_learned`、`evidence_index`、`unresolved_items`。不适用也要出现，写 `EMPTY` 或 `NOT_APPLICABLE`。

报告头部必写：被测版本、契约版本与哈希、环境类别、设备类别与固件、端点绑定方式、执行窗口、`formal_denominator = 有效正式样本`、排除样本清单及原因、复核人角色。

报告正文三条口径：自动判定与人工补充分列；通过率分子只算 `decision=PASS`，分母只算有效正式样本；每个结论都能回到 `run_id`、`manifest`、`verdict`、`verification`。

### 5.2 角色与签字点

| 角色 | 负责 | 不得做 | 签字点 |
|---|---|---|---|
| 验收负责人 | 排期、组织、汇总、跟缺陷 | 代替 Linux 写判定 | 执行记录、最终报告 |
| 需求负责人 | AC/REQ 覆盖、范围变化裁定 | 跳过批准放行 | 需求覆盖确认 |
| 控制面负责人 | 环境、数据库、证据存储、恢复演练 | 手工改判定或覆盖证据 | 环境就绪、恢复记录 |
| 节点设备负责人 | 节点、设备、端点、固件、串口音频链路 | 修改冻结工件或阈值 | 设备就绪、端点核对 |
| 证据管理员 | 目录、摘要、访问、保留、归档 | 删除或原地替换证据 | 证据索引、归档清单 |
| Linux 独立复核人 | 摘要重算、关联重建、分母与 oracle 复评 | 采信节点自报 PASS | 复核记录 |
| 安全隐私负责人 | 权限、脱敏、审计、越权检查 | 以验收便利放宽访问 | 安全隐私核对 |
| 所有者 | 冻结批准、残余风险接受、签收 | 缺证据时签 PASS | 冻结批准、最终签收 |

同一人可承担多个角色，但审批与复核仍是两个动作，复核记录不得因兼职而省略。

## 6. 退出准则与非声明规则

出口分类只允许四种：通过、有条件通过、阻塞、不通过。四选一，不写"基本通过""部分通过"。

### 6.1 写"通过"的七个条件

1. 计划内用例执行完毕，或每条未执行项有明确的无效、阻塞分类。
2. 每个正式 PASS 有完整证据、Linux 复核和可复算规则。
3. 分母可重建，烟测、模拟、历史重放均未混入。
4. P0 全部关闭，P1 有结论或书面风险接受。
5. 未决项、残余风险、回滚说明已登记。
6. 报告、证据目录、归档哈希、签字齐全。
7. 所有者或授权签字人明确签收，且发布授权单独存在。

任一条不满足，只能标"进行中""阻塞"或"不通过"。

### 6.2 不得写的话

| 禁止表述 | 原因 |
|---|---|
| 用 L0-L2 证据说 L3-L5 完成 | 层级不可替代 |
| 用 smoke run 样本拼正式分母 | 分母资格不允许 |
| 用节点自报 PASS 当结论 | 复核必须独立 |
| 用远程按需读取当备份或归档 | 未真实恢复 |
| 未演练就写 RPO/RTO 数值或目标值 | 只能写"未验证" |
| "已知问题不影响验收" | P0 未关闭不得绕过 |
| 验收通过即已发布 | 验收、发布、交付是三件事 |

### 6.3 与其他门的关系

正式 PASS 是样本级结论，验收通过是范围级结论，发布是运营决定，交付是移交决定。四者不得互相替代。报告可以写"通过"，发布记录必须另行存在。对外声明必须同时写版本、范围、证据层、环境边界。
