## Purpose

定义任务创建之后平台如何按业务域选择并推进工作流，让不同类别的任务走各自的步骤序列和 skill 触发点，而不是共用一条硬编码链路。该能力只约束编排行为与状态推进，不规定具体实现框架。

## ADDED Requirements

### Requirement: 业务域识别与工作流选择

平台 SHALL 在任务创建时确定业务域，并据此选择唯一一个已发布的工作流模板。识别来源可以是任务显式声明的类别、任务来源入口的默认类别，或由操作人手动指定。平台 MUST 记录所选模板的标识、版本和选择依据。若无法确定业务域，任务 MUST 停在 `AWAITING_CLASSIFICATION`，不得落入任意默认流程。

#### Scenario: 任务声明类别

- **WHEN** 创建任务时声明类别为 `voice-interaction`
- **THEN** 平台绑定 `voice-interaction` 的当前已发布工作流模板版本，并在任务上记录模板标识与选择依据 `declared`

#### Scenario: 无法识别类别

- **WHEN** 创建任务时既未声明类别，来源入口也没有默认类别
- **THEN** 任务进入 `AWAITING_CLASSIFICATION`，不启动会话，并返回需要人工指定类别的提示

#### Scenario: 手动覆盖类别

- **WHEN** 操作人对已创建且未进入终态的任务显式改派类别
- **THEN** 平台记录改派前后模板与操作人，新模板从第一步重新开始，旧模板的执行记录保留为历史

### Requirement: 编排步骤序列

每个工作流模板 SHALL 定义有序步骤集合，每个步骤 MUST 声明唯一标识、进入条件、退出条件、允许的 skill 触发点以及失败策略。平台 MUST 按顺序推进，未满足退出条件的步骤不得进入下一步。步骤状态 MUST 至少区分 `PENDING`、`READY`、`RUNNING`、`SUCCEEDED`、`FAILED`、`SKIPPED`、`BLOCKED`，且状态迁移 MUST 写入审计事件。

#### Scenario: 顺序推进

- **WHEN** 工作流第 1 步退出条件满足
- **THEN** 平台把第 1 步置为 `SUCCEEDED`，把第 2 步置为 `READY`，并记录一次状态迁移事件

#### Scenario: 提前跳步

- **WHEN** 当前步骤退出条件未满足而外部请求直接推进到后续步骤
- **THEN** 平台拒绝该请求，返回步骤未就绪的错误，当前步骤状态不变

#### Scenario: 条件跳过

- **WHEN** 步骤声明了可跳过条件且该条件成立
- **THEN** 步骤置为 `SKIPPED` 并记录跳过理由，流程继续到下一步

### Requirement: 编排中的 skill 触发点

工作流模板 SHALL 在步骤上声明 skill 触发点，触发点 MUST 指定 skill 标识、调用时机、输入契约和期望输出。平台 MUST 通过 skill 调度契约发起调用，不得在编排代码中内联某个 skill 的具体执行逻辑。触发点声明的 skill 不存在或版本不兼容时，模板校验 MUST 失败，该模板不得发布。

#### Scenario: 步骤触发 skill

- **WHEN** 流程进入声明了 skill 触发点的步骤
- **THEN** 平台按触发点契约调用对应 skill，并把调用记录与结果关联到该步骤

#### Scenario: 模板引用不存在的 skill

- **WHEN** 发布工作流模板时其中引用的 skill 标识未注册
- **THEN** 发布被拒绝，返回缺失的 skill 标识清单

#### Scenario: skill 结果不符合期望输出

- **WHEN** skill 返回结果不满足触发点声明的输出契约
- **THEN** 该步骤置为 `FAILED`，按步骤失败策略处理，且不得把结果写入下游步骤输入

### Requirement: 编排实例与任务版本绑定

平台 SHALL 为每个任务创建一个编排实例，实例 MUST 绑定任务修订版本和模板版本。任务修订变化时，编排实例 MUST 记录新的修订版本号，已执行步骤的历史记录不得被覆盖。同一任务同一时刻 MUST 最多只有一个处于活动状态的编排实例。

#### Scenario: 任务修订后继续编排

- **WHEN** 活动编排实例对应的任务产生新修订
- **THEN** 后续步骤基于新修订执行，实例记录修订号变化，已完成步骤的历史保持只读

#### Scenario: 重复创建实例

- **WHEN** 对已有活动编排实例的任务再次请求启动编排
- **THEN** 平台返回已有实例标识，不创建第二个活动实例

### Requirement: 暂停、恢复与终止

编排实例 SHALL 支持暂停、恢复和终止。暂停 MUST 在当前步骤到达安全点后生效，不得中断正在进行的 skill 调用或设备操作。终止 MUST 先执行已声明的清理动作，再置为终态。终态实例 MUST NOT 恢复。所有暂停、恢复、终止请求 MUST 记录请求人、原因和时间。

#### Scenario: 暂停

- **WHEN** 操作人请求暂停活动实例
- **THEN** 当前步骤完成后实例进入 `PAUSED`，未开始的后续步骤保持 `PENDING`

#### Scenario: 终止带清理

- **WHEN** 操作人请求终止活动实例且模板声明了清理步骤
- **THEN** 平台执行清理并记录清理结果，随后把实例置为 `STOPPED`

#### Scenario: 恢复已终止实例

- **WHEN** 对终态实例请求恢复
- **THEN** 平台拒绝请求，实例状态不变

### Requirement: 编排可观测性

平台 SHALL 提供编排实例的只读查询，返回当前步骤、已完成步骤、每个步骤关联的 skill 调用、证据引用和失败原因。事件流 MUST 按发生顺序可回放，且 MUST NOT 暴露凭据或未脱敏的节点输出。

#### Scenario: 查询实例进度

- **WHEN** 客户端查询活动实例
- **THEN** 返回当前步骤、步骤状态列表、skill 调用摘要和已产生的证据引用

#### Scenario: 回放事件流

- **WHEN** 客户端按实例读取事件流
- **THEN** 事件按时间顺序返回，敏感字段已脱敏，顺序与审计记录一致
